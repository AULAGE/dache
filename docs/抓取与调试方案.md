# 抓取方案与调试方案（v2）

> 2026-11-03 第一天真机联调后整理。依据：低平台上 15 次无底盘自动抓取的日志（11 次抓到）+ 当天所有调试记录。

## 1. 目标和边界

| | 现在 | 下一步 |
|---|---|---|
| 物块 | 24mm 方块，K230 能识别 | 同 |
| 放置平面 | **低平台**（机械结构够不到地面） | 地面需要改结构：机械臂在升降台上装低一点 / 加长爪子 |
| 无底盘 | 能抓深度约 **131~241mm**（两个标定姿态 ±25mm），左右靠底座转 | 中间深度加一个姿态，或做逆运动学（任务 05） |
| 有底盘 | 代码就绪，**未联调** | 按第 4 节分阶段上车 |
| 目标 | 真实成功率 ≥ 90%，误报成功 = 0，单次 ≤ 30 秒 | |

## 2. 抓取流程：现状、真机问题、改进

```
观察姿态 → 搜索 → 对准（闭环）→ 伸出 → 合爪 → 确认 → 放置
             ↑________ 没抓到：松开、退后、重试（最多 3 次）
```

### 2.1 搜索
- **现在**：先原地看一眼（看到要复核一次，防误识别）→ 转底座扫 → 换升降高度
- **真机问题**：没有
- **改进**：无

### 2.2 对准
- **现在**：每步测量 → 升降轴纠 y、底座纠 x（无底盘时目标按深度在近/远标定点之间插值）→ 学习灵敏度
- **真机问题**
  1. **K230 跟踪器锁住爪子脚**（爪子一只脚在画面左侧中间）：读数不随动作变化，底座一路转到 69°、升降轴一路降 10cm。
     现在有 ghost 检测，两步内停 —— 但只是止损，这次抓取就废了
  2. 底座 < 5° 的小修正转不到位（死区 / 回差），对准多走 2~3 步
  3. y 偶尔来回摆（±10~20mm）
- **改进**
  - **A. K230 端忽略爪子脚区域**（任务 10）：爪子脚相对相机永远不动，在 K230 程序里把这块画面的检测框直接丢掉，跟踪器就不可能锁上它。树莓派端再记一个 ghost "指纹"兜底
  - **B. 底座消回差**（任务 09）：最后一次修正统一从同一个方向逼近（反向时先多转 2° 再回来），并给小角度设最小有效步长
  - **C. y 摆动**：先看 B 和 A 做完后还在不在（多半是锁到爪子脚时的读数跳变）；还在就把 `STEP_ALPHA` 调到 0.7

### 2.3 伸出、合爪
- **现在**：张爪 → ready 姿态 → 按深度在 reach_near / reach_far 之间插值伸出 → 合爪；伸出前底座加微调 `GRASP_BASE_TRIM_DEG`
- **真机问题**
  1. **落点系统性偏右约 4mm**（对准误差已在容差内）：可能是爪子脚挡住物块左侧，K230 框中心偏右；也可能是回差
  2. 两个姿态在关节空间线性插值，**中间深度时爪子高度可能偏**（还没专门测）
  3. 爪子不能绕竖直轴转，物块歪着放时可能夹到角（"方向问题"）
- **改进**
  - **D. 固定微调**（已做）：`calib.py trim 4`
  - **E. 从结果学习微调**（任务 09）：没抓到时，重试**左右交替试探**（例如 −2mm、+2mm），哪个方向成功就把微调往那边挪一点；
    按深度分几段各学各的。这就是最初"用奖励学权重"的想法 —— 奖励 = 抓到没有，学的是落点偏差
  - **F. 中间姿态**：如果测试显示"中间深度失败、两端成功"，再标一个 reach_mid 做三点插值；彻底的办法是任务 05 逆运动学
  - **G. 方向**：K230 已经能输出物块的旋转角（OBB），但没有腕部旋转舵机，暂时只能在报告里统计"歪着放的成功率"，先摆正放

### 2.4 确认
- **现在**：`VERIFY = "observe"`：爪子合着退回观察姿态、升降轴降回原高度，看原位置还有没有物块
- **真机问题**：抬升确认（lift_check）被爪子骗（永远"抓到"），已弃用；observe 方式还没出现误判，但"物块被推开 10~30mm"时会误判为抓到
- **改进**
  - **H. 持物指纹**（先确认可行性，暂不开任务）：相机和爪子在同一节上，抓住的物块相对相机位置固定。
    如果抓着物块时 K230 画面里能看到它，就能标定一次"抓着时看到的位置"，抓起后直接确认"在爪子里"。
    但它的位置很可能就在爪子脚旁边，会和任务 10 的忽略区域冲突。**明天先在 IDE 里看：抓着物块时画面里能不能看到它、在哪**，能看到且不在爪子脚区域再做

### 2.5 放置、重试
- **现在**：底座转到 2287 放下 → 回观察姿态；失败时松开、退后（无底盘时不退）、重试最多 3 次
- **改进**：重试时配合 E 左右试探，不要原样再抓一次

### 2.6 速度
- 现在每次 15~40 秒，大部分时间花在机械臂动作（每个 1 秒）和确认上
- **改进**（最后做）：`ARM_MOVE_MS` 从 1000 试到 700；ready 姿态和 observe 一样时跳过；确认只做一种

## 3. 调试方案

### 3.1 每次上电
```bash
cd ~/grasp
python3 main.py --check          # 四个设备都在、K230 有心跳、升降轴 IDLE、电池电压
python3 selftest.py quick        # 改过代码才需要
python3 calib.py trim            # 看一眼当前微调
```

### 3.2 测试矩阵（每轮 18 次）
物块放在低平台上，**每个位置 2 次**：

| | 左（约 −10°） | 中 | 右（约 +10°） |
|---|---|---|---|
| 近（约 15cm） | ① | ② | ③ |
| 中（约 18cm） | ④ | ⑤ | ⑥ |
| 远（约 21cm） | ⑦ | ⑧ | ⑨ |

**一定要记"真的抓到没有"**（程序说的不算）。用试验记录工具（任务 08 做好后）：
```bash
python3 bench.py                 # 提示你放到哪个位置 → 自动抓 → 问你"真的抓到了吗" → 记录
python3 bench.py report          # 按位置统计真实成功率、误报、偏差方向
```
工具没做好之前：每次跑 `python3 main.py --once --no-chassis`，自己在纸上记位置和结果。

### 3.3 看什么 → 调什么

| 现象 | 多半是 | 调法 |
|---|---|---|
| 一直偏右（或左）几毫米 | 落点固定偏差 | `calib.py trim <偏右毫米>`（可累加） |
| 只有左边（或右边）的位置偏 | 和底座角度有关（回差 / 遮挡） | 记下来，等任务 09 的回差补偿；先摆中间 |
| 中间深度没抓到、两端抓到 | 插值误差 | 标 reach_mid（任务 09 一起做） |
| 远处偏高 / 偏低 | reach_far 标得不准 | `calib.py teach far` 重标 |
| 程序停下说"识别到机械臂自己" | 跟踪器锁住爪子脚 | 等任务 10；临时：把物块挪离画面左侧再试 |
| `lift_limit` | 平台太低 / 太高 | 换平台高度，或者重标（升降轴放中间高度标） |
| `report.py` 提示"x 来回过冲" | 步子太大 | `calib.json` 里 `STEP_ALPHA` 改 0.7 |
| 程序说抓到，实际没抓到 | 确认被骗 | 记下当时 `logs/run_*.log` 的确认那几行发给我 |
| 夹到了、路上掉了 | 夹得太浅（只夹到边） | 看是不是深度插值的问题；或者 `CLAW_CLOSE` 加一点 |

### 3.4 每轮结束
```bash
python3 report.py                # 程序视角
python3 bench.py report          # 真实视角（任务 08 之后）
```
把两份输出发给我。成功率 ≥ 90% 且误报 = 0 再进入第 4 节。

## 4. 底盘联调（无底盘稳定之后再做）

固件**没有串口超时停车**：树莓派死机时车会一直按最后的速度走。所以每一步都要有人守着电源。

1. **架空测试**（车轮离地）：`python3 chassis_test.py --timeout-check`，确认程序退出时车轮停下
2. **地面直走**：`python3 chassis_test.py`，±100mm 各 3 次，用尺子量；误差应 ≤ 5mm
3. **单步上车**：物块放在平台上、车离平台 40~60cm，`python3 main.py --once --step`，每一步看清楚再回车
4. **全自动**：`python3 main.py --once` → 连续多次 → 开机自启（`setup/grasp.service`）
