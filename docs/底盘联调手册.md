# 底盘联调手册（11/6 上车 → 11/9 晚决定比赛用不用底盘）

> 写于 2026-11-03（任务 18）。**本手册里的预期现象和数字来自固件源码分析和仿真，没有在真机验证**，以真机为准。
> 每一步做完把脚本输出贴到本文件末尾的记录表（或 `docs/cloud_tasks/results/` 新建一份），方便云端分析。

## 0. 先读这一节：安全

**固件没有串口超时停车**（任务 03 报告第 2 节）：树莓派这边停止发送，车会按最后一帧的速度一直走。树莓派端有这些保护：

| 情况 | 会不会停 | 靠什么 |
|---|---|---|
| Ctrl+C、程序正常退出、程序报错退出 | 会 | `close()` / `atexit` 直接写停车帧 |
| `systemctl stop grasp`、`kill`（不带 -9）、SSH 断开 | 会（任务 18 新加） | `main.install_stop_signals()`：SIGTERM / SIGHUP 当 Ctrl+C 处理 |
| 主线程卡死（没再刷新指令） | 0.5 秒后停 | `CHASSIS_CMD_TTL_S`：发送线程发现指令过期自动发 0 |
| 走到一半回传断了 | 0.5 秒内停并报错（任务 18 新加） | `drive()` 检查回传 |
| **`kill -9`、树莓派断电 / 死机、USB 线掉了** | **不会** | **只能拨底盘使能开关 / 断底盘电源** |

所以每一步都要：
1. **一个人手放在底盘电源开关（或使能开关）旁边**，另一个人操作电脑。开始前先确认开关在哪、拨一下车确实不动
2. 车**前方留 1m、后方留 0.6m、两侧留 0.5m** 空地；后退搜索（`SEARCH_BACKOFF_MM = 250`）是倒车，看不到后面
3. 第一次上车一律 `--once --step`（每个动作前回车确认），没问题再去掉 `--step`，最后才连续运行
4. 不要在 `main.py` 运行时开手柄（`pad_drive3.py` 会抢串口，程序会停车让出，但两边来回抢时车会抖）
5. 电池低于 22V 不跑（固件对 24V 电池没有有效的低压保护，见任务 03 报告第 8 节）
6. 开机后 10 秒内固件不收指令、陀螺仪在取零偏：**开机那 10 秒车不要动、不要碰**

## 3. 第 1 步：只读检查（车不会动）

```bash
python3 main.py --check
python3 chassis_test.py --voltage
```

**预期**：底盘有回传；电压 25~26V（满电）；开机 10 秒后 `flag=0`；静止时 `vx=0 wz=0`，陀螺仪Z 原始值在 ±30 以内。

**通过标准**：电压 ≥ 22V、`flag=0`、静止读数为 0。

| 现象 | 判断 | 处理 |
|---|---|---|
| 底盘没有回传 | USB 线 / 底盘电源 / 端口号 | `ls /dev/ttyACM*`；拔插 USB 口 1.2；看底盘电源灯 |
| `flag=1` 一直不变 | 源码里 1 = 电机失能（开机 10 秒内是 1） | 等 10 秒；看使能开关；仍是 1 就记下来（真机固件可能含义不同） |
| 手柄程序在运行 | 脚本拒绝启动 | `systemctl --user stop pad-watchdog`，断开手柄 |
| 陀螺仪Z 静止时很大 | 零偏没取好（开机时车动了） | 重新上电，开机 10 秒内别碰；或按一下底盘的用户按键重新取零偏 |

## 4. 第 2 步：架空测试（车轮离地）

用垫块把底盘垫起来，**四个轮子都离地**。

```bash
python3 chassis_test.py --hang
python3 chassis_test.py --timeout-check
```

`--hang` 依次测三种停车（每种车轮先转起来再看停不停）：
- A 指令过期：只发一次 80mm/s 不再刷新 → 0.5 秒后驱动自动发 0，车轮停
- B `close()`：持续发 1 秒后 close → 车轮停
- C SIGTERM：子进程持续发送，1.8 秒时对它发 SIGTERM → 车轮停

`--timeout-check` 不经过驱动直接发帧再停发：**预期停发后车轮继续转**（源码没有超时）。如果车轮停了，说明真机固件有超时，记下来（是好事）。

**通过标准**：`--hang` 三项全部 ✅。任何一项 ❌ **都不能下地**，把输出贴给云端。

| 现象 | 判断 | 处理 |
|---|---|---|
| 车轮没转起来（"最高 0mm/s"） | flag=1 / 使能开关关着 / 开机不到 10 秒 | 回到第 1 步 |
| 前进指令车轮倒转 | vx 符号和预期相反 | **停**，记下来；这种情况对准会越走越远，必须先解决（检查电机线、固件车型） |
| A ❌：车轮一直转 | 驱动的 TTL 没生效 | 看 `config.py` / `calib.json` 里 `CHASSIS_CMD_TTL_S` 是不是 0 |
| C ❌ | 信号处理没生效（旧版 main.py？） | 确认 `git pull` 到了任务 18 的代码 |

最后**手动确认一次**：`python3 chassis_test.py --timeout-check` 时（车轮在转）拨一下使能开关 / 电源，确认能停 —— 这是 `kill -9` / 死机时唯一的办法。

## 5. 第 3 步：地面直走精度

地上贴一条胶带当起点线；在车上选一个固定点（**后轴中点正下方**最好）对准起点线。车前后各留 0.5m。

```bash
python3 chassis_test.py --ruler --fresh          # 从默认 τ 开始学：+100×3、−100×3、+200×3、−200×3，每次输入尺子量的距离
python3 chassis_test.py --ruler --write          # 再跑一遍（接着上次学到的 τ），满意就写进 calib.json
```

每次走完量"固定点到起点线的距离"，输入正数（后退也输入正数）。可以每次把车推回起点，也可以以新位置为起点量。

**预期**：前两次误差大一点（τ 在学），第 3 次以后里程误差 ≤ 5mm；尺子 / 里程比例在 0.97~1.03；学到的 τ 在 0.3~0.6s。
早期"直走 100mm 实际 145mm"是没有滑行模型时的结果，现在应该没有了。

**通过标准**（第二遍）：
- 尺子误差：±100mm 平均 ≤ 5mm、最大 ≤ 10mm；±200mm 平均 ≤ 8mm、最大 ≤ 15mm
- 尺子 / 里程比例在 0.97~1.03
- 直走航向漂移 ≤ 3°/m（陀螺仪）

| 现象 | 判断 | 处理 |
|---|---|---|
| 尺子误差总是同一方向、和距离成正比（100 差 5、200 差 10） | 里程计比例不对（固件轮径参数和真车不同） | 记下"尺子 / 里程"比例。**对准是视觉闭环，不影响最终精度**，只会多走一两步；几何前馈按这个比例偏 |
| 尺子误差总是同一方向、和距离无关（都差 +20） | 滑行 τ 不对 | 多跑一遍让它学；还不行看 `--model` 模式：`python3 chassis_test.py --ruler --model` 对比 |
| 误差忽大忽小（±20mm 以上） | 打滑 / 地面不平 / 起步冲 | 换地面；`--speed 70` 降速再测 |
| 直走总往一边偏 > 3°/m | 转向没回正 | 按脚本提示填 `CHASSIS_YAW_TRIM_DEG_PER_M`（`calib.json`），再测一遍 |
| "底盘移动超时" | 车被卡住 / flag=1 | 看车轮是不是顶到东西 |

## 6. 第 4 步：最小转弯半径

车左右各留 0.6m、前方留 0.8m。在**后轴中点正下方**的地面做记号（或两个后轮着地点各做记号，取中点）。

```bash
python3 chassis_test.py --radius --write
```

脚本让车打满方向左转走 600mm 的弧、再右转走一段（每次走完把车摆回起点）。每次量两个数输入（空格分开）：
- **弦长**：起点记号到终点记号的直线距离
- **侧移**：终点记号离"起点处车头方向那条直线"的垂直距离（在起点沿车头方向拉一根线）

脚本按 R = 弦长² / (2 × 侧移) 算半径，取大的一边 +5% 写进 `ACK_MIN_RADIUS_MM`。直接回车会用陀螺仪推算（量程未验证，**不会写入**）。

**预期**：现在的 600mm 是估计值；仓库源码是 Mini 车（350mm），真车应该更大。

**通过标准**：左右两边都量到了，`calib.json` 里有了 `ACK_MIN_RADIUS_MM`。

| 现象 | 判断 | 处理 |
|---|---|---|
| 让它左转，车往右拐 | wz 符号反了 | **停**，记下来（协议里 wz 左转为正；反了对准会往反方向拐，必须先解决） |
| 左右半径差很多（例如 500 / 800） | 正常：源码里左右最大转角不同（−0.49 / +0.32 rad） | 程序取大的一边，安全 |
| 半径比 600 小 | 写进去以后底盘能拐得更急，对准步数少一点 | — |

仿真（真机近似，真实半径 900、配置仍是 600）：成功率 90%（配置正确时 88~98%），没有危险动作 —— 半径配错不危险，只是多走一步。

## 7. 第 5 步：量车头、摆场地（**防撞平台，很重要**）

有底盘时，程序会把车开到"相机离物块 `GOAL` 深度（真机约 156mm）"的地方。相机几乎在底座转轴上（`R_CAM_MM = 0`），
所以**底座转轴会停在离物块约 156mm 的地方**。

1. 量：**底座转轴到车头最前端（保险杠）的水平距离 F**，以及车头最前端的离地高度
2. 量：低平台的高度、物块离平台前沿的距离 E
3. 判断：
   - 车头能从平台**下面**伸进去（车头比平台低 / 平台下面是空的）→ 不会撞
   - 否则要求 **F + 30mm ≤ 156mm − E**，也就是物块离平台前沿最多 E = 126 − F（mm）。
     例如 F = 100mm → 物块离平台前沿不能超过 26mm；**F ≥ 126mm 时这个高度的平台根本没法用底盘去抓**（会撞）
4. 顺便把 `PIVOT_FWD_MM`（底座转轴在**后轴中点**前方多远）量一下写进 `calib.json`（几何前馈用，估错 50mm 也没事）

场地：物块放在车前方 40~60cm、左右 ±20° 以内（仿真：300~700mm、±30° 都试过，没有危险动作）。

## 8. 第 6 步：单步上车

```bash
python3 main.py --once --step --record
```

每个动作前打印要做什么（升降轴 / 机械臂 / **底盘走多少 mm、车头往哪拐**），回车才执行，`q` 停止。**底盘动作前看清楚方向和距离再回车**。

**预期**（仿真，真机标定近似）：搜索 → 对准 3~5 步（每步底盘走几十到几百 mm，边走边转）→ 伸出抓取 → 观察确认。
每次抓取底盘总里程平均约 260mm、最多约 550mm；不需要后退（加密搜索角之后）。

**通过标准**：连续 3 次单步抓取，每一步的底盘方向都对、没有撞到任何东西、程序最后的结果和人看到的一致。

可能看到的新提示（任务 18）：

| 提示 | 意思 | 处理 |
|---|---|---|
| "底盘动了两次，物块的读数几乎没变 → K230 识别到的很可能是机械臂自己" | `GHOST_CHECK_D`：车走了、读数不变 | 看 K230 画面识别框框在哪（多半是爪子脚）；这是对的保护 |
| "深度误差应约 …，读到 …，对不上（可能是误识别），再确认一次" | `CHASSIS_JUMP_CHECK` | 偶尔一次正常；**每次都出现**说明里程或深度标定有大问题，贴 `report.py` 输出 |
| "搜索：目标没有复现（可能是误识别），继续搜" | `SEARCH_CONFIRM_CHASSIS` | 偶尔正常；物块明明在却总说没复现 → K230 读数抖得厉害（看 `calib.py watch`） |
| "累计后退 …mm，不再后退" | `SEARCH_BACKOFF_MAX_MM` | 周围真没物块时正常；有物块就是太远 / 不在视野里，挪一下 |
| "底盘回传中断…已停车" | 走到一半收不到回传 | 检查 USB 线；**车已经停了** |

## 9. 第 7 步：全自动

```bash
python3 main.py --once --record          # 去掉 --step，连续做 10 次（每次手动摆物块）
python3 report.py                        # 每次失败后看自动诊断
```

**通过标准**：10 次里真实抓到 ≥ 7 次；**0 次危险动作**（见下）；平均每次 ≤ 60 秒。

**危险动作**（出现任何一次都按急停，记下来）：
- 车头或车身碰到平台 / 物块
- 一次抓取里离起点往后退超过 30cm
- 方向打满连续转了半圈以上（在兜圈）
- 对准时底盘一步比一步走得远（发散）
- 程序已经结束 / 报错，车还在动

连续运行（`python3 main.py`，不加 `--once`）**最后再试**，并且始终有人看着：没物块时它每隔几秒会重新搜索一次（后退累计最多 50cm 就不再退了）。

## 11. 11/9 晚：底盘用不用

**用底盘**，必须**全部**满足：

| # | 标准 | 从哪看 |
|---|---|---|
| 1 | 架空测试三项 ✅；使能开关 / 电源能可靠停车 | 第 2 步 |
| 2 | 联调全过程（第 6~8 步所有运行）**0 次危险动作**，0 次"程序结束了车还在动" | 记录表 |
| 3 | bench 有底盘真实成功率 ≥ 70%，且不比无底盘低超过 10 个百分点 | `bench.py report` |
| 4 | 有底盘平均每次 ≤ 60 秒 | `bench.py report` / `report.py` |
| 5 | 比赛场地上物块的位置**确实需要底盘**（超出无底盘可抓深度 131~241mm 或角度范围） | 比赛规则 |
| 6 | 车头不会撞平台（第 5 步的判断成立） | 第 5 步 |

**不用底盘**，出现任何一条：
- 有一次危险动作没查清原因、没修好并复测
- 架空测试任何一项 ❌，或 vx / wz 方向反了还没解决
- 有底盘成功率比无底盘低 10 个百分点以上，或者平均每次 > 90 秒
- 9 日晚还没跑完第 8 步（没有数据就不冒险）

**拿不准时不用**：无底盘现在 15 次抓到 11 次（低平台），比赛用无底盘 + 人工把物块摆进臂展内更稳。
决定不用时：`calib.json` 里写 `"USE_CHASSIS": false`（或一直加 `--no-chassis`），底盘断电。
