# 任务 01：控制参数自动搜索

## 背景
`raspberrypi/grasp/` 是全自动抓取的总控程序，用"闭环视觉伺服 + 自适应灵敏度"对准物块（见 `raspberrypi/README.md` 的"控制思路"）。
现在的控制参数大多是凭经验定的。`sim.py` 是仿真环境（相机深度系统误差、噪声、丢帧、K230 只在物块不碰画面边缘时发帧、
7 帧/秒、阿克曼底盘打滑和最小转弯半径、机械爪抓取容差、10% 随机抓取失败），`main.run_sim()` 能批量跑并统计。

用户最初的想法是"xy 越靠近 0 奖励越高、动作越少奖励越高"。`task.py` 里每次抓取都会算一个 `score`
（100×成功 − 2×步数 − 5×最终误差/容差 − 0.5×用时秒）。**本任务就是用这个分数在仿真里搜最优参数**——不训练神经网络，调的是控制参数。

## 目标
找出一组让**平均 score 最高、同时真实抓到率不下降**的参数，并给出每个参数的敏感度（调错了影响多大）。

## 搜索的参数（都在 `config.py`）
| 参数 | 现在 | 建议范围 |
|---|---|---|
| `STEP_ALPHA` | 0.85 | 0.5 ~ 1.0 |
| `LEARN_RATE` | 0.3 | 0.05 ~ 0.6 |
| `TOL` 三个轴 | x 1.5° / y 4mm / d 10mm | 各 ×0.5 ~ ×2（**注意**：容差太大抓取会失败——仿真里机械爪容差是 `SimArm.GRIP_TOL`） |
| `SAMPLE_N` / `SAMPLE_N_FAR` | 5 / 3 | 2~8 / 1~5 |
| `SETTLE_S` | 0.25 | 0.1 ~ 0.6 |
| `BASE_RECENTER_DEG` | 12 | 5 ~ 40 |
| `AXES[*]["max"]` | y 8cm / x 40° / d 400mm | 各 ×0.5 ~ ×1.5 |
| `SEARCH_BASE_DEG` / `SEARCH_LIFT_CM` | 见 config | 搜索顺序和步距（可以只比较几种候选方案） |
| `CHASSIS_SPEED_MM_S` | 100 | 50 ~ 200（仿真里速度只影响用时，要同时看 03 任务对停车精度的结论） |

**不要搜**：标定类参数（GOAL、POSES、R_CAM_MM、BASE_DIR…）——那是每台车量出来的，不是调出来的。

## 方法要求
1. 先跑基线：现在的参数，有底盘、无底盘各 ≥ 5 个种子 × 200 次，记录均值和标准差
2. 搜索方法自选（随机搜索 / 贝叶斯优化 / CMA-ES 都行，标准库能实现的优先；如果装第三方库要在报告里写明且不提交进仓库）
3. **每组参数至少 3 个种子 × 100 次**，防止拿噪声当结论；最终候选要用 10 个新种子复测（没参与搜索的种子）
4. 有底盘、无底盘两种情况分别给结论（`run_sim(..., no_chassis=True)`）
5. 单因素敏感度：最优点附近每个参数单独扫一遍，画出 score / 成功率 / 步数随参数变化的表（文本表格即可）
6. 写一个可复现的脚本 `raspberrypi/grasp/tools/param_search.py`（新建目录），能从命令行重跑

## 注意
- 跑仿真时修改的是内存里的 `config` 模块，不要改 `config.py` 文件本身的默认值；结论用 `calib.json` 格式给出
- `run_sim` 会改 `cfg.POSES`，每组参数前要 `importlib.reload(config)` 恢复（参考 `selftest.py` 的 `test_sim`）
- 如果发现仿真里某个现象明显不真实、影响结论，写进报告（任务 02 会处理），不要为了分数高去改仿真

## 交付物
- `raspberrypi/grasp/tools/param_search.py`
- `docs/cloud_tasks/results/01_报告.md`：基线、搜索过程、最优参数、复测结果、敏感度表、**推荐写进 calib.json 的值**（只写比默认值明显更好的，附提升幅度）
- 如果某些参数改了默认值更好，可以在报告里建议，但**不要直接改 config.py 默认值**

## 验收
- 推荐参数在 10 个新种子上：真实抓到率 ≥ 基线，平均 score 比基线高，差异超过两个标准误
- `python3 selftest.py` 全部通过
