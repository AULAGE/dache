## 问题清单（按严重程度）

编号后面写 **[已修]** 的是这次改了代码的；其余只报告。"复现"一栏的 `test_review.py` 用例名可以直接跑：
`python3 test_review.py TestReportedNotFixed.test_xxx -v`。

### 一、会伤硬件

#### H1 [已修] 升降轴复位（READY）后自动接着跑，零点可能是错的
- **现象**：升降轴下位机断电重启（`READY ... RST POR`）后固件认为自己在 0cm（readme："断电后重新上电，认为在最下端，可以直接运动"）。
  原来 `READY` 被当成普通 `DeviceError`：`main.py` 一直抓模式关设备、3 秒后重开、接着 `run_once`；`bench.py` 下一个位置也接着测。
  滑台如果复位时在 30cm，之后发 `A 44` 会再往上走 44cm → 撞到顶。`preflight` 也看不出来（`P` 回的是 `POS 0.00 IDLE`）。
  `grasp.service` 是 `Restart=on-failure`，带堆栈退出也会被拉起来再跑。
- **复现**：`TestLiftReset`（改之前 `run_real` 会重开设备，`opens == 2`）。
- **修复**：`devices.py` 新增 `DeviceResetError(DeviceError)`，收到 `READY` 抛它；`main.run_real` 收到后打印原因和处理办法，
  **正常退出**（退出码 0，systemd 不会重启）；`bench.py` 同样停止。普通 `DeviceError` 仍然重开再来（原行为）。

#### H2 [已修] `systemctl stop` / SSH 断开时进程被直接杀掉，底盘不停
- **现象**：SIGTERM（`systemctl stop grasp`，README 里调试前都要这么做）和 SIGHUP（SSH 断开，README 说经常发生）
  的默认处理是直接结束进程，`finally` 和 `atexit` 都不执行。底盘固件**没有串口超时**（任务 03），发送线程死掉前最后一帧是行驶帧，
  车会一直按这个速度跑；升降轴也收不到 `E`。`chassis_test.py --timeout-check` 时轮子会一直转。
- **复现**：`TestStopSignals.test_without_handler_last_frame_is_moving`（子进程里底盘行驶中收到 SIGTERM，最后一帧 vx=100）。
- **修复**：`main.install_stop_signals()` 把这两个信号变成 `KeyboardInterrupt`，走和 Ctrl+C 一样的停车流程。
  `main.py` 真机运行、`bench.py` 真机、`chassis_test.py` 启动时调用；仿真不调用。测试见 `TestStopSignals`（SIGTERM、SIGHUP 最后一帧都是停车帧）。

#### H3 [已修] 底盘行驶中回传中断，会全速开到超时
- **现象**：`WheeltecChassis.drive()` 开始时有回传，就按回传积分的里程判断走够没有。行驶中回传断了（USB 半掉、控制器卡住），
  里程不再增加，剩余距离一直不变，会以 `CHASSIS_SPEED_MM_S` 一直发指令，直到超时：400mm 的一步超时 = 400/30×1.5+3 ≈ 23 秒 ≈ **多开 2 米**。
  `CHASSIS_CMD_TTL_S` 防不住（指令一直在刷新）。
- **复现**：`TestChassisFeedbackLoss`（改之前 8 秒后才报"底盘移动超时"）。
- **修复**：行驶中 `has_feedback()` 为假（0.5 秒没收到状态帧，和启动检查同一个标准）就抛 `DeviceError`，`finally` 照常发 0。
  `SimWheeltec.has_feedback()` 恒为真，仿真不受影响。

#### H4 底盘 USB 线断开时车保持最后速度（固件限制，软件没法修）
- 发送线程写失败时固件收不到停车帧，又没有串口超时。这是厂家固件的问题（`底盘代码/` 只读）。
- **建议**：底盘联调（任务 18）时第一次先把车架空；底盘 USB 线用扎带固定；手边留底盘电源开关。

#### H5 机械臂没有急停
- Ctrl+C / 出错时机械臂停在当前姿态（Lobot 板子没有急停指令、也不回传）。如果当时是伸出姿态，爪子会一直压在平台 / 物块上。
  下一次 `run_once` 第一个动作是 `go_observe(0)`，先收回再动升降轴，所以**不会带着伸出的手臂升降**（已检查每个阶段）。
- **建议**：只报告。手动停止后如果爪子压着东西，用 `calib.py pose observe` 收回。

#### H6 消回差会让底座多转出 `BASE_BACKLASH_DEG`，超过 `BASE_LIMIT_DEG`
- `_arm()` 在底座已经转到 ±85° 时仍会先多转 `BASE_BACKLASH_DEG` 再转回来。默认 `BASE_CENTER=1500`、2° 时最多到 2466us，
  在舵机 500~2500 以内；但 `BASE_CENTER` 标定得偏、或者回差设得大时会被 `Arm.move` 截到 2500，截断后消回差也不完整。
- **建议**：`BASE_BACKLASH_DEG` 先用 1~2°；以后可以把"转过头"的目标也限制在 `BASE_LIMIT_DEG` 里（会抓错类改动，没做）。

### 二、会抓错

#### W1 底座死区让 GHOST_CHECK 误判，GHOST_FINGERPRINT 把真物块记成指纹（合并交互，最重要）
- **原理**：`align()` 里底座动了、读数几乎没变（< 30% 预期）连续 2 次 → 判 ghost。真机标定灵敏度 −0.6 时，
  只有 ≥ 2.5° 的底座步子才参加检查，而真机已知"底座小角度（< 5°）转动不到位"——正好落在这个区间。
  真物块被判 ghost 后，`GHOST_FINGERPRINT=True` 会把**真物块的读数**记进 `logs/ghosts.json`，以后在这个位置附近（±1.5°、±6mm、±15mm）
  的真物块一律当作没看到；`GHOST_FP_MIN_HITS=1`，记一次就生效，而且跨运行保存。
- **复现**：`TestReportedNotFixed.test_ghost_fingerprint_learns_real_block_when_base_has_deadband`。仿真（真机标定值 R=0、灵敏度 −0.6、底座方向 −1，`SIM_SERVO_DEADBAND_US=50`，5 台车 × 20 次）：

  | 设置 | 结果 |
  |---|---|
  | 死区 5us，指纹关 / 开 | 成功 93，ghost 0（两者一样） |
  | 死区 50us，指纹关 | 成功 36，**ghost 63** |
  | 死区 50us，指纹开 | 成功 27，ghost 28，**lost 42**；记下 28 个指纹，真物块被过滤 255 次 |
  | 死区 50us，指纹开 + `BASE_MIN_STEP_DEG=5` | 成功 63，ghost 16，lost 18 |

  （仿真里根本没有"爪子被识别成物块"，所以这些 ghost 全是误判。50us 是估计值，真机死区多大要看 `recorder.py backlash`。）
- **建议**：
  1. 明天先别开 `GHOST_FINGERPRINT`；`GHOST_CHECK` 保持开（它只是停下，不会记仇），但出现"底座动了两次读数没变"时先怀疑死区。
  2. 修法（下一步）：只在**升降轴**（y，丝杠很准）判定 ghost 时记指纹；或者记指纹前把执行器回到原位再测一次，读数仍不变才记；
     `GHOST_FP_MIN_HITS` 默认改成 2。
  3. 真要开，每轮跑完看一眼 `logs/ghosts.json`，记的是爪子脚（画面左侧中间，x 明显为负）还是物块位置。

#### W2 开了试探 / 学习时 bench 统计会被带偏
- `bench.csv` 的 `trim_deg` 列只记固定微调 `GRASP_BASE_TRIM_DEG`，不记学到的分段微调和试探量（`task.last_grasp` 里有 `trim_total_deg` / `probe_mm`，没写进 CSV）。
  人工报的"偏左 / 偏右"是最后一次（可能是试探过的）伸出的落点，`bench.py report` 按它给出的 `calib.py trim` 建议会错。
- **建议**：用 bench 做基线时关掉 `GRASP_PROBE_MM` / `TRIM_LEARN`；以后在 `FIELDS` 里加 `trim_total_deg`、`probe_mm` 两列，统计时扣掉试探量。

#### W3 升降轴离上限不到 5cm 时，观察确认在更低的高度看
- `grasp()` 合爪后 `move_by(+5)` 被 `LIFT_MAX_CM` 截断，`_observe_check()` 却按满 5cm 往下降，结果比抓取时低；放置后 `_lower_back()` 再降 5cm。
  真机 6mm/cm，低 3cm ≈ 物块在画面里偏 18mm，而"还在原位置"的判据是 |Δy| < 30mm，容易误判"抓到"。
- **复现**：`TestReportedNotFixed.test_lift_clamp_makes_observe_check_lower`（42cm 抓 → 44 → 39）。
- **影响**：明天在低平台上升降轴在下半段，碰不到。**建议**：抓取时记下实际抬了多少（`move_by` 返回值差），按实际值降回。

#### W4 指纹过滤会骗过观察确认
- `VERIFY="observe"` 时，原位置物块的读数如果正好在某个指纹里，`measure()` 返回 None → 判"原位置没有物块了 → 抓到"（误报）。是 W1 的后果，同样靠"先别开指纹"规避。

#### W5 `LIFT_LIMIT_SLACK_MM=15` 是按 10mm/cm 定的
- 真机升降灵敏度约 6mm/cm，15mm ≈ 2.5cm 的高度误差也会"按已对准处理"去抓。只在升降轴到 0 / 44cm 时生效，低平台上一般碰不到。
- **建议**：真机改成 9mm 左右（≈ 1.5cm），写进 `calib.json`（已在白名单）。

### 三、会报错退出

#### E1 [已修] 一直抓模式下串口异常 / 重开失败直接带堆栈退出
- **现象**：
  1. `run_real` 只接 `DeviceError`。pyserial 的 `SerialException` 是 `OSError`——升降轴 USB 掉线时 `readline()` / `write()` 抛的就是它；
     `ARM_USB_ROBUST=False` 时机械臂连续掉两次也抛它（config 注释里写着"主程序退出"）。都会冲出主循环。
  2. 设备错误后重开，`open_devices` 抛错（USB 正在重新枚举、J-Link 串口暂时不在）不在 try 里，直接退出。
  3. `open_devices` 打开一半失败时，已经打开的 K230 读线程不会停；如果被重试，**两个线程抢同一个串口**，帧会被拆碎。
- **复现**：`TestReopenAndSerialErrors`（改之前 2 个 ERROR、1 个 FAIL）。
- **修复**：`run_real` 和 `bench.RealRig` 把 `OSError` 和 `DeviceError` 一样处理（关设备、3 秒后重开）；
  已经通过启动检查之后重开失败就等 3 秒再试；第一次打开失败、`--once` 仍按原样报错；`open_devices` 失败时关掉已打开的设备。

#### E2 `REACH_NEAR_D == REACH_FAR_D` 时 `reach_pose` 除零（没修，概率很小）
- `calib.py teach` 两次深度四舍五入后正好相等才会发生（"不标远处"分支会设成 near+70，不会相等）。`goal_for` 有这个保护，`reach_pose` 没有。
- **复现**：`test_reach_pose_divides_by_zero_when_near_equals_far`。**建议**：`reach_pose` 里分母为 0 时直接用 `reach_near`。

#### E3 `calib.json` 里 `TOL` / `GHOST_FP_TOL` 只写一部分轴会整体替换（没修）
- 例如写 `"TOL": {"x_deg": 2.0}`，`y`、`d` 就没了，第一次 `in_tol()` 就 `KeyError` 退出。`calib.py` 自己不会写出这种文件，手改时会。
- **复现**：`test_partial_tol_in_calib_json_crashes`。**建议**：`_apply_calib` 对字典型参数（`TOL`、`GHOST_FP_TOL`、`GOAL*`）做合并而不是替换；或者 `--check` 时检查键齐全。

#### E4 日志写不进去（SD 卡满 / 只读）时会出错
- `_save_trim()`、`recorder.write()`、`steps.csv` 写失败抛 `OSError`。修 E1 之前是直接退出；修之后会被当成设备错误，关设备、3 秒后重开、再失败……
  一直循环（不危险，但抓不了）。`--record` 每帧都写 jsonl，长时间开着要留意空间。
- **建议**：明天开 `--record` 前 `df -h` 看一下；以后记录器写失败只打印一次、不抛出。
