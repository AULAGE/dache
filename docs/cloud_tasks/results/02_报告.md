# 任务 02 报告：让仿真更真实

分支：`cloud/02-sim-fidelity`　日期：2026-11-02
**所有结论都只来自仿真和离线自测，没有在真机上验证。** 标"估计"的参数没有实测依据，需要真机确认。

## 一句话结论

- 7 个真实因素都加进了 `sim.py`，每个都有 `config.py` 的 `SIM_*` 开关，**默认开启**；全部关掉时和原版仿真**逐位一致**（同 seed 的成功率、步数、用时、评分完全相同）。
- 全部打开后，有底盘成功率 **93.3% → 87.5%**，无底盘 **95.7% → 96.7%**；平均用时有底盘 41→57s、无底盘 37→45s。
- 影响最大的是 **7 误识别**（有底盘 −5 个百分点）；**6 USB 掉线**会让程序**直接崩溃**（原代码的漏洞）；**2 底盘平滑**暴露了"底座转到极限 → 抓空 → 误报抓到"的控制逻辑漏洞。
- 针对这三个问题做了三个**默认关闭**的改进开关（A/B/C），全打开后有底盘回到 **93.3%**、无底盘 **97.1%**，"报成功但没抓到"从 11 次降到 0 次（/1000）。
- 另外发现 `config.FOV_X_DEG / FOV_Y_DEG` 很可能和 K230 旋转后的画面**反了**（见第 6 节），如果属实，仿真成功率会掉到 55~65%。**需要真机确认**。
- `python3 selftest.py`：**52 项全部通过**（原 36 项 + 新增 16 项），85% 阈值没有动。

## 2. 每个因素的模型和真实依据

| # | 因素 | 仿真里怎么做 | 参数 | 依据 |
|---|---|---|---|---|
| 1 | K230 跟踪器预测 / 滞后 | 每 1/7 秒一帧（±10ms 抖动），每帧走一遍和板子 `Tracker` **同样的**关联（中心距离 < 0.8 框长）、中值（3 帧，运动大时 2 帧）、自适应 EMA（按帧间隔换算）、0.6px 死区、2 帧确认、丢帧时 holding（预测但**不发**）、丢 6 帧重置；`touches_edge`（框边离画面边 4px）不发。动作执行期间的帧位置按时间插值，且只有 50% 能检出（运动模糊）。`measure` 和真机 `K230.measure` 一样：收 `since` 之后的帧，凑够 n 帧或 1.5s 超时 | `SIM_K230_TRACKER=True`，`SIM_BLUR_DETECT_P=0.5`（**估计**） | 常数全部抄自 `k230_sdcard/main.py`（`CONFIRM_FRAMES=2`、`LOST_TOLERANCE=6`、`SMOOTH_WINDOW=3`、`ALPHA_MIN/MAX`、`MOTION_REF`、`DEADBAND_PIX`、`EDGE_MARGIN`、`FOCAL_PIX=944`）；7 帧/秒来自 `config.K230_FPS` 的实测 |

## 4. 逐项分析

### 1 K230 跟踪器：成功率反而略升，用时增加
- **滞后确实存在**：底座右转 3° 后，第一帧只报了 40% 的位移（−7.5mm，真实 −19.8mm），第二帧 87%，约 0.4s 后收敛。但 `SETTLE_S=0.25` 加上"只收 since 之后的帧"，第一帧基本被丢掉，剩下的滞后被 5 帧中值吸收，所以对准步数没有变多（4.03 → 3.84）。大动作（> 0.8 个框长 / 帧）时跟踪器会先 holding 2 帧再换目标、重新确认，这时是"晚到"而不是"滞后"。
- **为什么成功率升了**：原版仿真两处过于悲观：① 3% 丢帧是"整次测量直接作废"，逐帧后只是少一帧；② 碰边缘判断用"中心角 + 半个物块角"相加，比 K230 的像素判断（框边离画面边 4px）严约 1.5mm。无底盘时物块离相机只有 130~200mm，竖直可视窗口约 ±52mm，而 `SEARCH_LIFT_CM_NEAR` 间隔正好 10cm——差 1.5mm 就决定能不能扫到，所以无底盘 not_found 从 41 降到 11。
  → **这说明无底盘的搜索高度间隔没有余量**，真机上物块恰好在两个搜索高度之间时容易漏。建议近距离高度间隔缩到 8cm（例如 `[25, 17, 33, 9, 41, 1]`），交给任务 01 搜索确认。
- **用时增加**：看不到物块时，逐帧模型要等满 `MEASURE_TIMEOUT_S=1.5s` 才返回（和真机一样），原版只等 n/7 秒。搜索一圈多 3 秒左右。

### 2 底盘平滑：用时 +5s，暴露一个控制逻辑漏洞
- 停车误差现在来自真机 `drive()` 的真实行为：τ 学习后停车误差多数 < 6mm；但 τ 的估计会偏小（真值 0.45s，学到 0.36~0.40s），因为驱动在回传速度 < 5mm/s 时就认为停稳了，剩下的蠕动没计入。这是**真机也会有**的偏差，量级 2~3mm，可以接受。
- 用时 41 → 47s：`drive()` 快到终点时按剩余距离降速 + 等车停稳，走 100mm 实际要 3.3s（原版仿真按 1.3s 算）。
- **漏洞（"报成功但没抓到" 1 → 6~9 次）**：阿克曼边走边转时，**实际转过的角度比指令小**（松油门滑行时 vx=0，固件把前轮回正；转向舵机也有滞后。例：指令走 200mm 转 15°，实际 11.6°）。几次之后底座被几何前馈推到 `BASE_LIMIT_DEG=85°`，此时如果深度刚好在容差内，`align` 里 `u_d=0`、`u_x` 被限幅成 0，走到"剩下的误差小于最小动作，没法更好了" → **带着 14° 的 x 误差去抓**，必然抓空；又因为伸出后看不到物块、观察确认时物块在画面外，判成"原位置没有物块了 → 抓到"。
  → 改进 C（见第 5 节）。

### 3 舵机死区 / 回差：影响不显著
- 单项 −0.4 / −0.1 个百分点，在统计误差内；对准步数 +0.2（底座小角度修正有时一步不到位要多走一步）。
- 隐患：`AXES["x_deg"]["min"]=0.3°` ≈ 3.3us，**小于 5us 死区**，0.3~0.45° 的修正指令舵机根本不动；回差 10us ≈ 0.9°，接近 `TOL["x_deg"]=1.5°` 的一半。目前容差够宽所以没出问题。
- 建议（未改）：真机测一下死区后，把 x 的 `min` 提到死区以上（如 0.5°）；如果以后收紧 x 容差，可以在 `set_base` 里做换向回差补偿（换方向时多走半个回差）。

### 4 伸出时碰歪物块：无底盘时抓取失败明显增加
- 单项：有底盘 −1.5、无底盘 −1.8 个百分点；grasp_failed 2 → 15 / 1 → 13。
- 有底盘时被推开后能退后、重新对准、再抓，多数能救回来（多 0.3 步、+2s）。
- **无底盘时救不回来的典型过程**：物块被往外推 20~30mm → 深度超出 `REACH_FAR_D`，插值截断到 t=1 → 伸不到 → 再推一次……直到 3 次用完。这是物理限制（没有底盘，够不着就是够不着）。
- 这个因素的参数全是估计，结果对 `SIM_PUSH_P` 很敏感：降到 0.15 时全开默认有底盘 88.7%、无底盘 97.2%。
- 建议（未改，需要真机先观察到这种现象）：
  1. 伸出前在 `ready` 姿态再测一次（相机离物块更近、更准），偏差大于抓取容差的一半就退回 observe 再对一步；
  2. 无底盘时抓取失败后，如果新的深度 > `REACH_FAR_D`，直接报"够不着"并停下，不要再伸（省时间、也不会把物块越推越远）。

### 5 深度随距离非线性：没有明显影响
- 单项（和第 1 项一起开）：94.6% / 98.9%，与只开第 1 项持平，步数略少。原因：抓取发生在 160mm 附近，那里 1px 偏差只有约 1mm 深度误差，而 GOAL 是按 K230 读数标定的，固定偏差被标定吸收；远处（900mm 时 ±34mm）的误差只会让远距离那几步走得不准，靠闭环和学习吸收掉了。
- 累加时 −0.7 / −0.3 个百分点，在统计误差内。
- 注意：远处深度误差大，`AXES["d"]` 的灵敏度 J 是在不同距离混着学的，非线性会让学到的 J 偏向远处的值；目前 J 被限制在初值的 1/4~4 倍且学习率 0.3，没看到问题。

### 6 USB 掉线：会让程序直接崩溃（原代码漏洞）
- 单项：每 1000 次有 **2 次崩溃**（有底盘、无底盘都是）。原因：`Arm.move` 掉线后只重连、重发**一次**；如果重连后第一帧又掉（接触不良时很常见），第二次写入抛出的是 `serial.SerialException`，不是 `DeviceError`，`main.run_real` 不捕获，**整个程序退出**（`--once` 以外的连续运行模式也会退）。
- 另一个隐患：掉线那一帧可能"写进缓冲区没报错但没发出去"，`Arm` 却以为舵机已经到位（控制板不回传）。
- → 改进 A：`ARM_USB_ROBUST`。

### 7 误识别：影响最大
- 累加 −5.0 个百分点（有底盘），单项 −2.1；用时 +7s。
- 典型过程：搜索时底座转到某个角度，正好冒出一个持续 4~5 帧的假目标 → 凑够 3 帧中位数 → 被当成物块 → 对准第一步就朝它开 400mm 并打方向 → 下一次测量假目标没了 → "目标丢失" → 重新搜索，但车已经开走、真物块不在视野里 → 3 次机会用完。
- 敏感性：发生率减半（`SIM_FALSE_TARGET_P=0.0025`）时全开默认有底盘 90.3%。
- → 改进 B：`SEARCH_CONFIRM`。

## 5. 控制逻辑改进（都有开关、默认关闭 = 原行为）

| 开关 | 改了什么 | 效果（全开仿真，1000 次） | 代价 |
|---|---|---|---|
| A `ARM_USB_ROBUST = False` | `devices.Arm`：掉线后在 `RECONNECT_S`（5s）内**反复**重连；重连成功后把**所有舵机的最新位置**和这一帧合并整帧重发（补上可能静默丢失的上一帧）；最终失败报 `DeviceError`（主程序会关设备、3 秒后重开，不会退出） | 崩溃 2 → 0（两种模式） | 无 |
| B `SEARCH_CONFIRM = False` | `task.search`：第一次看到目标后原地再测 1~2 次，深度/y 差 ≤ max(30mm, 15%)、方位角差 ≤ 3° 才采信；看不到或对不上就继续搜 | 有底盘 87.6% → 92.6%，lost 59 → 2；用时 −5s | 每次找到目标多约 1s |
| C `BASE_LIMIT_BACKUP_MM = 0` | `task.align`（阿克曼）：底座想转的角度超过 `BASE_LIMIT_DEG`、x 还没对准、而深度已在容差内时，后退这么多并把车头往物块方向拐，下一步再往前对深度（原来会直接去抓） | 报成功没抓到 7 → 0；成功率 92.6% → 93.3% | 偶尔多一步 |

- 在**原版仿真**（新因素全关）下打开 A+B+C：有底盘 93.3% → 93.7%，无底盘 95.7% → 95.2%（统计误差内），用时 +1s。**不会让原来的情况变差**。
- 三个开关都加进了 `CALIB_KEYS`，可以在 `calib.json` 里打开做真机对比。
- 默认值全部关闭时，`task.py` / `devices.py` 的行为和改之前完全一样：用原版仿真复测，同 seed 的结果逐位一致（例如 seed 31 有底盘 40 次：37/40、4.2 步、38.4s、63.1 分，和改之前的 selftest 输出相同）。
- **建议真机按 A → C → B 的顺序打开试**：A 只影响掉线时的行为、没有副作用；C 只在底座顶到极限时触发；B 会改变搜索节奏，先观察 K230 实际误识别多不多。

## 6. 额外发现：视场角配置可能反了（需要真机确认）

`k230_sdcard/main.py`：AI 画面是 1280×720，`ROTATE_DEG = 90`、`POSITION_IN_ROTATED_FRAME = True`，所以发出来的 X 是在**旋转后 720 宽 × 1280 高**的画面里算的（`compute_position` 里 `pw, ph = frame_h, frame_w`）。按 `FOCAL_PIX = 944`：

- 水平半视场 ≈ atan(360/944) = **20.9°**，竖直半视场 ≈ atan(640/944) = **34.1°**
- 而 `config.py` 是 `FOV_X_DEG = 35`、`FOV_Y_DEG = 25`，看起来正好是没旋转时的水平值。

`FOV_*` 只用于仿真和人为设计搜索角度，控制逻辑本身不用，所以我**没有改默认值**。但如果真机确实是 21°×34°：

| 条件（全开 + A+B+C） | 有底盘 | 无底盘 |
|---|---|---|
| FOV 35°×25°（现配置） | 93.3% | 97.1% |
| FOV 21°×34° | **63.0%** | **55.0%** |
| FOV 21°×34° + 搜索角加密 `SEARCH_BASE_DEG=[0,±38,±76,±85]`、`SEARCH_BASE_DEG_NEAR=[0,±25,±50,±75]` | 84.5% | 71.5% |

主要是水平视场窄了，现在 ±55° 的搜索步距之间有 13° 的空隙，对准时物块也更容易滑出画面。
**真机确认方法**：物块放在相机正前方 300mm，慢慢往右移到 K230 刚好不再发位置帧，记下最后一帧的 X 和 D，半视场 ≈ atan(X/D) + 半个物块角；上下同理。确认后改 `FOV_X_DEG / FOV_Y_DEG`，再让任务 01 重新搜索 `SEARCH_*` 参数。

## 7. 其它观察（没有改）

- **有底盘 not_found 约 5%**（原版仿真就有）：场景里物块离车 300~1200mm，而 `SIM_MAX_DETECT_MM=900`；搜索都没找到时 `SEARCH_BACKOFF_MM=250` 会**后退**再搜，对太远的物块反而更远。这是场景/搜索策略问题，留给任务 01（例如"没找到就往前开一段再搜"）。
- **观察确认的判据偏乐观**：`_observe_check` 里"看不到物块"一律当成"抓到了"。底座在极限、物块在画面外时会误判（改进 C 消除了最主要的触发场景）。如果以后还有误报，可以考虑"看不到时再转一下底座看看"。
- 仿真速度：全开后 100 次约 1 秒（逐帧模型只在需要时补算帧），任务 01 可以放心大规模搜参数。
