## 0. 一页结论

仿真：无底盘、10 台车 × 100 次；环境 = 任务 09 的真实因素（落点偏右 3~5mm、横向容差 ±5mm、底座回差 20us、R=0）
\+ 真机现在的做法（`VERIFY="observe"`、`trim 4`）+ 新加的"合爪没夹住时 50% 概率把物块推开 10~40mm"。

| 配置 | 真实抓到率 | **误报成功** | 平均用时 s | 学到的底座 J 偏差 |
|---|---|---|---|---|
| ① 现状（任务 13 全关） | 79.0% | **108（10.8%）** | 47.3 | −6.7% |
| ② 整画面确认 `VERIFY_WHOLE_FRAME` | 83.2% | **0** | 48.5 | −6.9% |
| ③ 去掉确认前 carry `VERIFY_SKIP_CARRY` | 79.0% | 106 | 45.6 | −7.0% |
| ④ 动作时间缩放 `ARM_MOVE_SCALE` | 79.7% | 112 | 41.5 | −6.6% |
| ⑤ 同向才学 J `LEARN_SAME_DIR_ONLY` | 82.3% | 96 | 46.6 | **−0.5%** |
| **⑥ 任务 13 全开** | **85.5%** | **0** | **41.6** | **−0.8%** |
| ⑦ 现状 + 任务 09 试探学习 | 74.7% | 155（15.5%） | 47.3 | −5.5% |
| ⑧ 任务 13 全开 + 任务 09 试探学习 | 84.0% | **0** | 41.9 | −2.7% |

1. **整画面确认消除了所有误报**（不管推开概率是 0、0.2 还是 0.5，见第 3 节），真实抓到率还略升（误报时程序直接去放置、
   这个物块就丢了；现在会重试）。代价是被推开时多测一次（约 1 秒）。
2. **任务 09 的落点学习最怕误报**：误报多时打开学习反而更差（⑦ 74.7% < ① 79.0%，误报 10.8% → 15.5%）；
   先开整画面确认再开学习（⑧）就没有这个问题。所以**整画面确认必须在任务 09 学习之前打开**。
3. **提速**：两项提速一起，平均每次少约 5.7 秒（仿真）。按 `config.py` 里真机姿态（arm.txt 的脉宽）估算，
   抓到一次时机械臂动作时间 **9.9 秒 → 5.9 秒**，没抓到一次 7.6 → 4.3 秒（第 4 节）。
4. **灵敏度学习去偏**：回差 20us 时 J 偏差 −6.7% → −0.5%；回差 40us 时 −7.8% → −0.5%。真实抓到率也 +3 个百分点
   （J 准了，对准少过冲）。仿真里的偏差（约 7%）比任务 11 报的 13~17% 小，见 5.2。

## 1. 改了什么

| 文件 | 改动 |
|---|---|
| `config.py` | 新参数（默认全关，加进 `CALIB_KEYS`）：`VERIFY_WHOLE_FRAME` `VERIFY_WHOLE_MIN_D_MM` `VERIFY_SKIP_CARRY` `ARM_MOVE_SCALE` `ARM_MS_PER_US` `ARM_MIN_MS` `LEARN_SAME_DIR_ONLY`；仿真 `SIM_CLAW_PUSH_P` `SIM_CLAW_PUSH_MM` `SIM_CLAW_PUSH_MAX_EN`（也默认关） |
| `task.py` | 所有机械臂指令都改走 `_send()`（动作时间缩放在这里，**协议和脉宽不变**，只改时间）；`grasp()` 可跳过确认前的 carry；`_observe_check()` 原位置没物块时可再看整个画面（`_whole_frame_check()`）；`run_once()` 结果新增 `pushed`、被推开过就跳过任务 09 的落点学习；`align()` 里底座 J 只在同向时学习 |
| `sim.py` | 新因素 11：合爪没夹住时、物块离爪子不太远（偏差 ≤ 3 倍抓取容差）就有概率被推开 10~40mm（往物块偏的那侧、朝外 0~60°）。用独立随机数流，关闭时不抽随机数 |
| `sim_speed_verify.py`（新） | 本报告所有表格的来源 |
| `selftest.py` | 新增 `test_speed_verify`（27 项）+ 仿真回归"无底盘、任务 13 全开" |

`devices.Arm` 没改；`bench.py` 没改（`prog_result` 会出现新值 `pushed`，它按"不是 success"处理，统计不受影响）。

### 1.1 整画面确认 `VERIFY_WHOLE_FRAME`
```
观察确认：原位置（±6°、±30mm、±40mm）还有物块 → 没抓到（和原来一样）
          原位置没有 → [新] 画面里别处还有吗？
                         有 → 再测一次（排除一闪而过的误识别）→ 还有 → "物块被推开了 Δx Δy Δd" → 没抓到，结果 pushed
                         没有 → 抓到
```
- 爪子脚：K230 端（任务 10）已经在发帧前丢掉忽略区域；树莓派端 `measure()` 本来就会过滤 ghost 指纹，所以这里不用再处理
- `VERIFY_WHOLE_MIN_D_MM`：**抓着的物块回到观察姿态时如果在画面里**（第 2.4 节 H 还没确认），它会被当成"还有物块"→ 永远判没抓到。
  这时把这个值设成比"抓着时看到的深度"大一点，比它近的读数不算。默认 0 = 不排除
- 一次抓取里第一次判 pushed 后重试抓到了，结果仍是 `success`；最后没抓到、且最后一次是被推开的，结果是 `pushed`
- 打开时 `episodes.csv` 多一列 `pushes`（关闭时列不变，旧的 `report.py` 不受影响）

### 1.2 去掉确认前的 carry `VERIFY_SKIP_CARRY`
只在 `VERIFY="observe"` 时生效：合爪 → 抬升 → ~~carry~~ → 直接回观察姿态确认 → 抓到了才收回 carry → 放置。
**注意**：伸出姿态直接回观察姿态，中间不经过 carry，舵机走的是关节空间直线，路径和原来不同。真机第一次开要 `--step` 看一眼会不会刮到平台。

### 1.3 动作时间缩放 `ARM_MOVE_SCALE`
`ms = min(原值, max(ARM_MIN_MS, Δ最大脉宽 × ARM_MS_PER_US))`：
- 只会更快、不会更慢；伸向物块那一步（`ARM_SLOW_MS`）不缩放
- 程序记住发给每个舵机的最后脉宽；**不知道某个舵机在哪时用原来的时间**：刚启动、换了机械臂设备对象（重开串口 / 单步模式）、
  USB 重连过（`Arm.reconnects` 变了）都会清空记忆。因为机械臂板重新上电时舵机会回到上电姿态，按记忆算时间会太快
- 默认 `ARM_MS_PER_US=0.8`（LDX-218 空载约 0.16s/60° ≈ 0.24ms/us，留了 3 倍余量）、`ARM_MIN_MS=200`。
  动作快了相机晃得更厉害，后面的 `SETTLE_S`（0.25s）可能要加一点，真机上看对准步数有没有变多

### 1.4 同向才学 J `LEARN_SAME_DIR_ONLY`
`align()` 里底座这一步的转动方向和上一次底座转动方向（任何来源：搜索、对准、伸出、回观察姿态都算）不同，就不用这一步学 J。
换向那一步一部分被回差吃掉，学进去 J 会偏小。和任务 09 的消回差同时开时，最后一段总是同一方向，等于每步都学。

## 2. 仿真模型：合爪推开物块（`SIM_CLAW_PUSH_P`）
- 合爪后没夹住（偏差超出抓取容差，或者 10% 随机失败那一档），物块离爪子不太远（偏差 / 抓取容差 ≤ 3）时，
  以 `SIM_CLAW_PUSH_P` 的概率推开 `SIM_CLAW_PUSH_MM`=10~40mm
- 原来就有的 `SIM_PUSH_P`（伸出时蹭到，默认 0.3）不变；所以即使推开概率 = 0，现状也有 2% 误报（第 3 节）
- 推开后的物块如果还在原位置容差内，原来的确认就能发现；推出容差、但还在画面里 → 原来的确认误报、整画面确认能发现；
  推出画面 → 两种确认都会误报（仿真里没出现，因为 10~40mm 在 18cm 深度上只有 3~13°，画面半宽 35°）

## 3. 推开概率的敏感性（10 台车 × 100 次）

| 推开概率 | ① 现状 抓到率 / 误报 | ② 整画面确认 | ⑥ 任务 13 全开 | ⑧ 全开 + 任务 09 学习 |
|---|---|---|---|---|
| 0（只有原来伸出时的推开） | 85.0% / 20（2.0%） | 86.1% / **0** | 88.7% / **0** | 88.6% / **0** |
| 0.2 | 81.9% / 72（7.2%） | 84.9% / **0** | 87.8% / **0** | 87.9% / **0** |
| 0.5（主表） | 79.0% / 108（10.8%） | 83.2% / **0** | 85.5% / **0** | 84.0% / **0** |

程序发现推开的次数和"现状"的误报次数基本相等（0.5 时 108 次误报、整画面确认发现 108 次），说明原来的误报几乎全是"推开了但还在画面里"。

## 4. 提速（按真机姿态估算，`python3 sim_speed_verify.py --arm-time`）

仿真里姿态之间的脉宽差是假的（只用 3 号舵机区分姿态），所以另外按 `config.py` 里 arm.txt 的真机脉宽走一遍"伸出 → 确认 → 放置"，
统计机械臂动作要等的时间（`Arm.move` 每帧等 ms + 0.15s；不含升降轴和 K230 测量）：

| 配置 | 抓到一次 s | 没抓到一次 s | 动作帧数（抓到） |
|---|---|---|---|
| 现状 | 9.90 | 7.60 | 10 |
| 去掉确认前 carry | 8.75 | 6.45 | 9 |
| 动作时间缩放 | 6.17 | 4.62 | 10 |
| 两项都开 | **5.89** | **4.34** | 9 |

两项都开时每帧的时间：张爪 200（原 300）、ready 200（原 1000，和 observe 一样，只差底座微调）、伸出 1200（不变）、合爪 500（不变）、
回观察 587（原 1000）、carry 200（原 1000）、放置 629、松爪 400、回观察 629。
真机每次 15~40 秒里机械臂动作约 10 秒，这两项能省约 4 秒；**用你自己的 `calib.json` 姿态数字会不一样**，在树莓派上跑一下：
```bash
cd ~/grasp && GRASP_IGNORE_CALIB= python3 sim_speed_verify.py --arm-time
```
（脚本默认忽略 calib.json；把环境变量清空就会读真机的姿态。）

## 5. 灵敏度学习去偏

### 5.1 回差大小 × 学习方式（10 台车 × 100 次，最终 J 和真值 −1 的偏差）

| 底座回差 | 每步都学（原行为） | 同向才学 | 抓到率（每步 / 同向） |
|---|---|---|---|
| 0us | −0.2%（−1~+1%） | −2.0%（−16~+0%） | 86.1% / 85.7% |
| 20us（≈1.8°） | **−6.7%**（−14~−1%） | **−0.5%**（−2~+0%） | 79.0% / 82.3% |
| 40us（≈3.6°） | **−7.8%**（−19~+0%） | **−0.5%**（−2~+1%） | 62.8% / 65.0% |

- 没有回差时两种一样（−2.0% 那一档是一台车最后一步的指数平均落在 −16%，其余 9 台都在 ±1% 内：J 是快照，有噪声）
- 同向才学平均每次抓取跳过约 0.8 步（回差 20us，10 台车 × 100 次共跳过 776 步），换向主要出现在"搜索转过去 → 对准转回来"的第一步

### 5.2 为什么仿真里的偏差（约 7%）比任务 11 报的 13~17% 小
- 任务 11 是在它自己的仿真世界（`research/sim_world.py`，回差 0.5~3°、随机激励）里测的，换向很多；
  `task.py` 的对准流程大多是"一次换向 + 几步同向"，被污染的步数比例小
- `AdaptiveAxis.learn` 本来就会丢掉"方向反了"的步，并把幅度限制在 1/4~4 倍，回差吃掉整步时这一步不学
- 结论：偏差方向一致（偏小），同向才学都能去掉；真机上偏多少要看真实回差

### 5.3 还没解决的
- 换向后第一步如果比回差还小，间隙没走完，下一步虽然同向也还有一点回差。任务 11 建议的"并且 |u| 明显大于回差"没做
  （回差大小未知，要等任务 11 的辨识或真机测量）

## 6. 真机打开顺序建议

每步跑一轮测试矩阵（`bench.py`，18 次），**一定记真实结果**，和上一轮比。

1. **`VERIFY_WHOLE_FRAME`**（先开，风险最小、收益最大）
   - 开之前先在 IDE 里看：**抓着物块回到观察姿态时，画面里看不看得到它？** 看得到就记下 K230 读的深度，
     `VERIFY_WHOLE_MIN_D_MM` 设成比它大 20mm 左右；看不到就保持 0
   - **工作区只能放一个物块**（第二个物块会让程序永远判"没抓到"）；周围有像物块的东西也会
   - 看日志里"物块被推开了 Δx Δy Δd"出现的次数和方向：推开总往一边 → 和任务 09 的落点偏差有关
2. **`LEARN_SAME_DIR_ONLY`**：只影响学习，最坏是学得慢一点。开之后看 `steps.csv` 里 `J_x_deg` 是否比原来更接近标定值（约 −0.6）
3. **任务 09 的 `GRASP_PROBE_MM` + `TRIM_LEARN`**：在 1 之后开（误报会让学习学错方向，见主表 ⑦）
4. **`VERIFY_SKIP_CARRY`**：第一次用 `--once --step` 看伸出 → 观察姿态这段路径会不会刮到平台 / 物块
5. **`ARM_MOVE_SCALE`**：最后开。先用保守值 `ARM_MS_PER_US=1.0`，看动作有没有冲击、相机晃不晃、对准步数有没有变多；
   没问题再降到 0.8。晃得厉害就把 `SETTLE_S` 从 0.25 加到 0.35

calib.json 里加（例）：
```json
{"VERIFY_WHOLE_FRAME": true, "LEARN_SAME_DIR_ONLY": true, "VERIFY_SKIP_CARRY": true,
 "ARM_MOVE_SCALE": true, "ARM_MS_PER_US": 1.0}
```
