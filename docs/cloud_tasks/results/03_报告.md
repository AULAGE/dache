| 证据 | 出处 |
|---|---|
| 源码是 **Mini 小车**版本：工程名 `F407VET6_Mini小车_STM32源码_2022.01.26(霍尔编码器).hex`，阿克曼轮距 0.162m、轴距 0.144m、轮径 65mm | `BALANCE/robot_select_init.h:37`、`:45`、`:84` |
| 电压在发送前被**限到 12.6V**：`if(Voltage>=12.6f)Voltage=12.6f;` | `BALANCE/show.c:47`，发送 `HARDWARE/usartx.c:106` |
| 但真机回传电压 ≈ **25.8V** | 任务说明里的实测 |
| 仓库里的 `.hex` 和这份源码一致（我把 hex 解出来搜常量：12.6f、0.35f、0.144f、0.32f、−0.49f、636.56f 都在） | 解析 hex 的脚本见第 7 节 |

所以**真机跑的是另一个版本的 WHEELTEC 固件**（24V 大车版），和仓库源码"同一家、同一套框架"，但参数（轮距、最小半径、电压保护、PI 参数）
可能不同，甚至可能有源码里没有的功能（比如平滑、超时）。下面每一条都按"源码是这样写的"回答，并注明哪些需要真机确认。

还有一个和真机对得上的地方：按源码的 PI 速度环推出来的滑行距离"和速度成正比"，只要电机增益合适，正好就是实测的 100mm/s 滑约 45mm（见第 1 题）。
所以真机固件的速度环很可能和源码一样。

编译进工程的文件以 `USER/WHEELTEC.uvprojx` 为准：`BALANCE/control.c`、`filter.c`、`HARDWARE/exti.c`、`dma.c`、`stmflash.c` **没有编译**
（`control.c` 是更老的平衡车代码，里面的 `Turn_Off(voltage<1110)` 之类不生效）。

## 1. 速度平滑 `Smooth_control()`

**算法**（`BALANCE/balance.c:699-718`）：每 10ms 调用一次（控制任务 100Hz，`BALANCE/balance.c:170-172`）
- 指令 > 0：`VX += 0.01`（m/s），指令 < 0：`VX -= 0.01`，即**加速度 1 m/s²**，再限幅到 `±|指令|`
- 指令 == 0：`VX *= 0.9`，即每 10ms 衰减 10%（时间常数 ≈ 95ms）
- 到达 100mm/s 需要 10 拍 = **100ms**；松油门后滑行 ≈ v × 0.01 × 0.9/0.1 = **v × 0.09s**（100mm/s 时 9mm）

**串口控制时是否启用**：**阿克曼车型不启用**。只有麦轮车、全向轮车才调用：
`if(Car_Mode==Mec_Car||Car_Mode==Omni_Car) { Smooth_control(...) }`（`BALANCE/balance.c:22-33`，注释原话"全向移动小车才开启速度平滑处理"）。
阿克曼分支 `BALANCE/balance.c:70-107` 直接用原始 `Vx`。

**那松油门后滑 45mm 是哪来的？** 来自增量式 PI 速度环（`BALANCE/balance.c:378-397`，`KP=KI=700`，`BALANCE/system.c:49`，输出限幅 ±16800）。
增量式 PI 有一个恒等式：从稳态（误差≈0）把目标置 0，到电机停下，PWM 的总变化 = KI × Σ误差，所以

```
滑行距离 = v × τ_PI，  τ_PI = 0.01s / (KI × KV)      （KV = 每 1 个 PWM 对应的稳态车速）
```

- **和速度成正比**（现在驱动的"τ × 速度"形式是对的），和电机时间常数、摩擦无关
- **和电池电压成反比**（KV ∝ 电压）：25.8V→22.5V，滑行多约 15%（100mm/s 时多 6~7mm）
- 实测 45mm/100mm/s → τ_PI ≈ 0.45s → KV ≈ 3.2×10⁻⁵ m/s/PWM（满 PWM ≈ 0.53m/s），对 24V 带减速箱的大车是合理量级
- 如果松油门时车正在被 RAMP 减速（PI 积分低于稳态），滑得会比 τ·v 少；这正是自适应 τ 要学的部分

离线验证（selftest 里按源码复现的假控制器）：50/100/150mm/s 三种速度 τ 都是 0.440s；22.5V 时 0.505s（理论 0.516s）。

## 2. 串口指令超时

**源码里没有超时停车**。查过的地方：
- 串口 3 中断 `HARDWARE/usartx.c:645-705`、串口 1 `:450-525`、串口 5 `:714-774`、CAN `HARDWARE/can.c:309-336`：只在收到合法帧时写 `Move_X/Move_Y/Move_Z`
- 控制任务 `BALANCE/balance.c:164-228`：每 10ms 直接用 `Move_X, Move_Y, Move_Z`（`:192`），没有计时、没有清零
- 全工程搜 `Move_X=0`：只在 APP 遥控（`balance.c:435-464`）和航模遥控开头 1 秒（`balance.c:634`）里出现

**结论**：最后一帧的速度会**一直保持**。树莓派程序崩溃 / 被 `kill -9` / USB 线掉了，车会按最后的速度一直走，直到使能开关拨到 OFF（`HARDWARE/motor.h:62` 的 `EN`，`balance.c:328`）或断电。

对驱动的影响：
- 50Hz 持续发送**不是固件要求的**，但要保留：每一帧都会把控制权从 PS2/航模抢回来（见第 7 题），而且发 0 的帧就是"刹车"
- 原驱动注释"停发会自动刹车"是错的（已改）
- 新增了三层保护（见第 9 节）：指令过期自动发 0、`close()` 直接写停车帧、进程正常退出时 `atexit` 写停车帧。
  **`kill -9`、断电、USB 掉线这三种情况树莓派端无能为力**，只能靠使能开关
- 真机验证方法：`python3 chassis_test.py --timeout-check`（**必须先把车架空**），看停发后轮子是否继续转

## 3. 下发帧：单位、限幅、阿克曼转角换算

帧解析 `HARDWARE/usartx.c:660-700`：`7B` 开头、第 11 字节 `7D`、前 9 字节异或 = 第 10 字节（`Check_Sum(9,0)`，`:901-921`）。
**第 2、3 字节（下发帧里的 `00 00`）固件不读**。开机后 10 秒内（`CONTROL_DELAY=1000` 拍，`BALANCE/system.h:99`）收到的字节直接丢掉（`usartx.c:653-656`）。

| 字段 | 单位 | 限幅 | 出处 |
|---|---|---|---|
| vx | int16，mm/s → m/s（整数除法 + 余数×0.001，精度 1mm/s） | 只在轮速上限 ±3.5m/s | `usartx.c:690`、`:829-840`；`balance.c:20`、`:102-103` |
| vy | 同上；阿克曼车型不用 | — | `usartx.c:691` |
| wz | int16，0.001rad/s，**ROS 约定左转为正**；阿克曼车型被换算成**右前轮转角** | 转角 −0.49 ~ +0.32 rad，舵机 PWM 800~2200 | `usartx.c:692-696`、`:784-820`；`balance.c:82`、`:106` |

**阿克曼 wz → 转角**（`Vz_to_Akm_Angle`，`usartx.c:784-820`）：
1. `R = vx / wz`（转弯半径，m）；若 `|R| ≤ 最小半径 0.35m`，把 wz 降到 `|vx|/0.35`（`:801-809`）
2. `右前轮转角 = atan(轴距 / (R + 轮距/2))`（`:812`）
3. 再在 `Drive_Motor` 里：舵机 PWM = `1500 + (−0.628a³ + 1.269a² − 1.772a + 1.573 − 1.572) × 636.56`（`balance.c:97-98`，`SERVO_INIT=1500` 在 `HARDWARE/motor.h:65`）；
   两个后轮按半径分速 `A = vx(R−W/2)/R`、`B = vx(R+W/2)/R`（`balance.c:87-88`）

也就是说**阿克曼车的 wz 实际是"曲率"指令**（R = vx/wz），不是角速度闭环。驱动里 `wz = 曲率 × v` 跟着速度一起变、保证走同一条弧，这个做法和固件一致。

**vx = 0 时**：`if(Vz!=0 && Vx!=0)` 不成立 → 转角 = 0（`usartx.c:797`、`:814-817`）→ **方向立刻回正**，wz 被忽略。所以：
- 不能原地转（驱动里 `turn()` 报错是对的）
- 每次松油门（发 vx=0）方向盘立刻回正，松油门后滑的那 30~45mm 是**直线**。弧线最后一段会比计划的弯得少，`drive()` 返回的实测航向会反映出来，任务层用实测值闭环，问题不大

**倒车时 wz 的符号**：wz 始终是"车体的偏航角速度，左转为正"，和前进还是后退无关。倒车 + wz>0 → R<0 → 前轮往右打 → 车头往左转。
驱动的 `drive(mm<0, dpsi)` 发的 wz 不乘方向，所以"车头右转 dpsi"在倒车时也成立。离线测试：前进 200mm、后退 200mm 都要求右转 10°，实测 +9.9° / +10.7°。

组帧 `HARDWARE/usartx.c:40-148`，发送任务 **20Hz**（`usartx.c:20-22`），串口 1/3/5 发同样内容（`:26-28`）。所有 16 位量都是**大端有符号**（`short`，`HARDWARE/usartx.h:20-36`）。

| 字节 | 内容 | 单位/量程 | 出处 |
|---|---|---|---|
| 0 | `7B` | | `usartx.c:108` |
| 1 | **flag = `Flag_Stop`**：1 = 软件失能（电机不出力），0 = 正常。开机前 10 秒为 1，之后清 0 | | `usartx.c:109`；`ICM20948/ICM20948.c:369-378`；`BALANCE/system.c:24` |
| 2-3 | vx：两个后轮编码器平均 | mm/s | `usartx.c:62-63`；轮速换算 `balance.c:686-687` |
| 4-5 | vy：阿克曼恒为 0 | | `usartx.c:64` |
| 6-7 | wz：**编码器**差速 `(B−A)/轮距` | 0.001 rad/s，左转为正 | `usartx.c:65` |
| 8-13 | 加速度 X/Y/Z：ICM20948 **原始值**，轴已换到 ROS 坐标（X=芯片Y，Y=−芯片X） | 量程 ±2g → **16384 LSB/g** | `usartx.c:88-90`；`ICM20948.c:88` |
| 14-19 | 角速度 X/Y/Z：原始值，减过开机零偏；**flag=1 时 Z 发 0** | 量程 ±500°/s → **65.5 LSB/(°/s)** | `usartx.c:93-102`；`ICM20948.c:85`、`:383-391` |

| 22 | 前 22 字节异或 | | `usartx.c:145` |
| 23 | `7D` | | `usartx.c:147` |

要点：**wz 来自编码器，不是陀螺仪**。阿克曼车的两个后轮速度是固件按"指令转角"分配的（第 3 题），所以转向机构没回正（机械偏差）时，
编码器 wz 看不出来，**只有陀螺仪 Z 看得出来**。实测"直走航向 −2°"如果是用回传 wz 积分得到的，说明真机固件和源码的分速方式不一样，值得在真机上对比一下两种航向（测试脚本会同时打印）。
陀螺仪零偏在开机 10 秒内取（`ICM20948.c:33-36`），**开机那 10 秒车必须静止**；单击用户按键可以重新取零偏（`balance.c:648-653`）。

## 5. 最小转弯半径 / 最大转角

- 源码：`MINI_AKM_MIN_TURN_RADIUS 0.350f`（`BALANCE/robot_select_init.h:31`），右前轮转角限幅 −0.49 ~ +0.32 rad（`balance.c:82`）
- 两者自洽：外侧轮 0.32rad 时 R = 0.144/tan(0.32) − 0.081 = 0.353m；内侧轮 0.49rad 时也是 0.353m
- **但这是 Mini 车（轴距 144mm）的值**，真机大车的轴距、转角都不同，350mm 不能直接用

所以 **`ACK_MIN_RADIUS_MM` 没改，仍是 600**，只在 `config.py` 里补了出处注释。固件会把更急的弯截到它自己的最小半径（`usartx.c:801-809`），
树莓派端用比固件大的值不会被截，是安全的。测法：方向打满（发 `vx=100, wz=1000`，固件会自己截到最小半径）走一圈量直径；或者用测试脚本走一段弧看航向。

## 7. 其他会让车动的输入源和切换规则

控制任务里的优先级（`BALANCE/balance.c:183-192`）：**APP 蓝牙 > 航模遥控 > PS2 手柄 > （CAN / 串口 1/3/5 的 Move_X/Y/Z）**。各来源怎么"抢"控制权：

| 来源 | 什么时候接管 | 出处 |
|---|---|---|
| 串口 3（默认 ROS 口） | **每收到一帧合法帧**就把 PS2/APP/航模/CAN/串口1/串口5 标志全清 0 | `usartx.c:681-686` |
| 串口 1 / 串口 5 | 收到合法帧就置自己的标志并清其他标志 | `usartx.c:495-505`、`:750-755` |
| CAN（ID 0x181） | 收到就置 CAN 标志并清其他 | `can.c:317-320`（`CAN1_RX0_INT_ENABLE=1`，`can.h:8`） |
| PS2 手柄 | 按过 Start 后，左摇杆往前推（`PS2_LY<118`） | `pstwo.c:117-125` |
| 航模遥控 | 通道 2 脉宽 > 1600us | `timer.c:167-177` |
| 蓝牙 APP（串口 2，9600） | 连续收到两个 `0x41`（APP 前进键） | `usartx.c:549-554` |

- 所有来源都要开机 10 秒以后才生效（`CONTROL_DELAY`）
- 树莓派 50Hz 发帧时，PS2/航模/APP 一旦接管，**下一帧（20ms 内）就被串口抢回来**，然后它们再抢……会来回打架。
  所以现有的 `ManualGuard`（检测到 `pad_drive3.py` 在运行就停车让出串口）是对的做法。`pad_drive3.py` 本身也走同一个串口，不涉及固件切换
- 树莓派的 USB 口接的是串口 1 还是串口 3，源码看不出来（两者帧格式、解析完全相同，`usartx.c:450-525` vs `:645-705`），不影响使用
- 自检模式（`Check`）恒为 0（`system.c:98`），`robot_mode_check()`（满 PWM 判乱转后失能，`balance.c:740-748`）没有被调用

## 8. 低电压保护

- 源码：`Turn_Off()` 在 `(int)Voltage < 10` 时禁止电机（`balance.c:325-339`），10.5V 蜂鸣一次、10V 再响（`show.c:48-49`）——这是 **12V（3S）Mini 车**的阈值
- 电压测量：`ADC × 3.3 × 11 × 1.03 / 4096`（`HARDWARE/adc.c:4`、`:112`），量程到 37V，能测 24V 电池
- 对 24V 大车，源码里的 10V 保护**等于没有保护**（真机固件阈值未知，查不到）

**`BATTERY_MIN_V = 22.0` 是合理的，保留**：实测满电 25.8V，如果是 6S 锂电（满 25.2V）22V = 3.67V/节，偏保守、安全；
如果是 7S 锂电（满 29.4V，25.8V 是半电）22V = 3.14V/节，接近放电下限，再低就伤电池了。**建议看一下电池标签确认节数**：7S 的话可以保持 22V，6S 的话可以降到 21V 多跑一会儿。
因为固件不管，这一项必须由树莓派把关（`config.py` 已加注释）。

## 9. 驱动改进（`raspberrypi/grasp/devices.py` 的 `WheeltecChassis`）

所有新行为都由 `config.py` 开关控制，**默认保持原来的松油门做法**；新增参数都加进了 `CALIB_KEYS` 白名单。

| 改动 | 默认 | 说明 |
|---|---|---|
| `CHASSIS_STOP_MODEL = "tau"` / `"model"` | `"tau"`（原做法） | `model`：预计滑行 = v ×（指令延迟 `CHASSIS_CMD_LATENCY_S`=0.02s + τ_PI × 参考电压/当前电压），并用回传帧的"年龄"外推里程（20Hz 回传，最多旧 50ms = 5mm）。τ_PI 也自适应学习，和 τ 一起存在 `logs/chassis_tau.json` |
| 自适应 τ | 保留 | 两种模式下都继续学 τ（兜底：模型参数异常时自动退回 τ） |
| `CHASSIS_CMD_TTL_S = 0.5` | 开 | 指令 0.5 秒没刷新就自动改发 0。`drive()` 每 20ms 刷新一次，正常使用不受影响；防的是主线程卡死时车一直走（固件没超时） |
| `close()` / `atexit` | 开 | 不经过发送线程，直接往串口写 3 帧停车帧 |
| `CHASSIS_YAW_TRIM_DEG_PER_M = 0.0` | 关 | 转向没回正时的补偿：每米右偏多少度，驱动在 wz 上叠加反向的曲率；**倒车时乘方向**，保证前轮往同一边打（机械偏差和方向无关） |
| 回传解析 | — | 新增 `fb_flag`、`fb_wz`、`gyro_z_raw`、`yaw_gyro`（陀螺仪积分，只做对比）、`last_release`（每次松油门的记录） |
| 超时报错 | — | 底盘超时时如果 flag=1，提示"固件电机失能：开机不到 10 秒？" |
| `main.py` 启动前检查 | — | flag=1 时打印 ⚠ 提示（**只提示不拦截**，flag 含义未在真机确认） |

`ACK_MIN_RADIUS_MM`、`BATTERY_MIN_V` 的默认值没改（理由见第 5、8 题）。

### 为什么 model 模式值得在真机上试
1. **电压补偿**：电池从 25.8V 用到 22.5V，τ 模式会多滑约 5mm，model 模式自动修正（离线：model −1.6mm / tau +4.5mm）
2. **里程外推**：回传只有 20Hz，原做法用的里程最多旧 50ms
3. 两种模式在电压不变时差不多（都在 ±4mm 内），所以默认仍用 τ，等真机对比后再决定

## 10. 离线测试（`selftest.py`，云端运行，**不是真机**）

新增 `test_chassis_fw`：按源码逐步复现阿克曼固件（串口收帧 → mm/s 换算 → `Vz_to_Akm_Angle` → 阿克曼逆解（不平滑）→ 增量 PI → 20Hz 回传，
没有超时）。固件之外的电机是假设的：一阶惯性 60ms + 库仑摩擦 500PWM + KV 取得让 τ_PI=0.45s。原来的一阶滞后假控制器测试也保留。


## 附：怎么确认仓库里的 hex 和源码一致

把 `F407VET6_Mini小车_STM32源码_2022.01.26(霍尔编码器).hex` 按 Intel HEX 解成二进制，用 `struct.pack('<f', x)` 搜源码里的浮点常量：
`12.6f`（`show.c:47`）出现 2 次、`0.35f`、`0.144f`、`0.32f`、`-0.49f`、`636.56f` 各 1 次，说明 hex 就是这份 Mini 车源码编出来的。
如果以后能从真机控制板读出固件（ST-Link `st-flash read`），用同样的方法搜 `25.2f`、`22.2f` 之类的常量，就能知道真机固件的电压阈值和车型参数。
