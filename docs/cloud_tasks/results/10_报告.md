## 1. K230 端改了什么（`k230_sdcard/main.py`）

配置在开头新增的"忽略区域（爪子脚，云端任务 10）"一节：

| 配置 | 默认 | 作用 |
|---|---|---|
| `IGNORE_REGIONS_ENABLE` | `True` | 总开关。`False` 时和改之前的行为完全一样 |
| `IGNORE_REGIONS` | `[(0.00, 0.40, 0.12, 0.60)]` | 忽略区域列表，每项 `(左, 上, 右, 下)`，0~1 归一化，**基于 IDE 里看到的旋转后画面**，左上角 (0,0)、右下角 (1,1)。可以写多块 |
| `IGNORE_DRAW` | `True` | 在 OSD 上用红色虚线框画出区域，左上角标 `IGN` |
| `IGNORE_CALIB_MODE` | `False` | 标定辅助：终端持续打印每个检测框的归一化中心、宽高、面积，以及是否在区域里 |
| `IGNORE_CALIB_EVERY_MS` | `200` | 标定打印的最小间隔 |

默认区域宽 0.12、高 0.20，面积约 **1/42**，比用户看到的爪子脚（约 1/60）略大一圈。判断依据是**检测框中心**，
所以区域只要包住"爪子脚被识别时框的中心"就够了，不需要包住整只脚。

主循环里的位置（顺序很重要）：

```
检测后处理 aicube → [标定模式打印] → 丢掉中心在区域里的框 → tracker.select → 颜色精修 → tracker.update
  → [锁定目标进区域？是就 tracker.reset()] → 画 OSD（先画区域虚线框）→ 算位置 → 发串口
```

- 被丢掉的框完全不进跟踪器，所以跟踪器**不可能**锁上它；画面里只剩爪子脚时，K230 就只发心跳（D=0），树莓派当成"没看到"。
- "已锁定目标进入区域"看的是平滑后的框中心；丢帧保持（预测）中看预测框中心。进入时终端打印 `Target entered ignore region, dropped.`
- 区域在启动时换算成原始像素矩形和 OSD 线段，主循环里只做几次比较，几乎不占时间。启动时终端会打印两种坐标下的区域，方便核对：
  ```
  ignore regions (display 0~1): [(0.0, 0.4, 0.12, 0.6)]
  ignore regions (raw 1280x720 px): [(512, 634, 768, 720)]
  ```

### 坐标换算（离线测试固定下来了）

检测框在 AI 分辨率 1280×720（原始画面）下；`ROTATE_DEG = 90` 是顺时针转 90°，`rotate_point(x, y) = (720 − y, x)`，
用户看到的画面宽 720、高 1280。所以：

| 显示画面（归一化） | 原始画面（像素） |
|---|---|
| 横向 u（0 = 左，1 = 右） | y = (1 − u) × 720　（**显示画面的左边 = 原始画面的下边**） |
| 纵向 v（0 = 上，1 = 下） | x = v × 1280 |

`test_region_to_raw_pixels_rot90` 把这个换算钉死：默认区域 → 原始像素 x ∈ [512, 768]、y ∈ [633.6, 720]。
`ROTATE_DEG = 0 / 270` 也都测了来回换算一致（`unrotate_point` 是 `rotate_point` 的逆）。

OSD 图层和画面区域重合，所以区域在 OSD 上就是 `u × OSD_W, v × OSD_H`，和识别框用的是同一套坐标 ——
**只要识别框平时画在物块上，红色虚线框就画在区域真正生效的位置上**。（如果哪天改了 `VO_FLAG_INVERT`，以 OSD 上的虚线框为准。）

## 2. 树莓派端改了什么（`raspberrypi/grasp/`）

`config.py` 新增（都加进了 `CALIB_KEYS` 白名单，可以写在 `calib.json` 里）：

| 配置 | 默认 | 作用 |
|---|---|---|
| `GHOST_FINGERPRINT` | `False` | 总开关。关着时和改之前完全一样（不写文件、不过滤） |
| `GHOST_FP_TOL` | `{"x_deg": 1.5, "y": 6.0, "d": 15.0}` | 读数三项**都**在容差内才算"和指纹接近" |
| `GHOST_FP_MIN_HITS` | `1` | 同一个指纹被判 ghost 几次后才开始过滤（怕误记可以设 2） |
| `GHOST_FP_MAX` | `10` | 最多保留几个指纹，满了丢掉最久没命中的 |
| `GHOST_FP_FILE` | `"ghosts.json"` | 文件名，放在 `logs/` 下 |

`task.py`：
- `align` 判定 ghost（原来的逻辑不变：动了两次读数几乎不变）时，调用 `record_ghost(m2)` 把当时的读数（x_deg、y、d）记下。
  和已有指纹接近就合并（取平均、命中次数 +1），否则新记一个。
- `measure()` 每次测量后检查 `ghost_match(m)`：接近某个指纹就返回 `None`（当作没看到），并打印
  `看到的是之前记录的假目标（ghost 指纹 #1：x=… y=… d=…，记录于 …），当作没看到。如果这其实是真物块，删掉 logs/ghosts.json`。
  搜索、对准、确认都经过 `measure()`，所以都生效。
- 爪子相对相机不动，它的读数和机械臂姿态、升降高度、底座角度都无关，所以记一次以后都认得出（前提是爪子开合状态一样）。

`ghosts.json` 样子：
```json
{"note": "...", "tol": {"x_deg": 1.5, "y": 6.0, "d": 15.0},
 "ghosts": [{"x_deg": 4.2, "y": 18.0, "d": 160.0, "hits": 1, "first": "2026-11-04 10:00:00", "last": "...", "seen": 0}]}
```
文件坏了不会崩溃（打印一句、当作没有指纹）。

**风险（为什么默认关）**：如果 ghost 是误判的（比如升降轴卡住不动，真物块的读数也不会变），就会把**真物块的位置**记成指纹，
之后那个位置的物块都"看不见"。所以打开后每次过滤都会打印提示；看到"之前记录的假目标"而画面里明明是物块，就删掉 `logs/ghosts.json`。

**局限**：指纹只是兜底。如果 K230 的跟踪器锁着爪子脚，树莓派这边只能"不信它"，没法让 K230 转去看真物块 —— 这就是根因要在 K230 端处理的原因。

## 4. ⚠️ 真机 ghost 读数和"左侧中间"对不上

按代码算（`test_left_middle_box_reads_negative_x`）：中心在显示画面 (u, v) 的框，发出去的方位角 ≈ `atan((u·720 − 360) / 944)`，和框大小无关：

| 框中心在显示画面 | 方位角 x_deg | Y |
|---|---|---|
| 默认区域中心 (0.06, 0.5) | **−19°** | 0 |
| 区域右上角 (0.12, 0.4) | −16.5° | −20mm（框 150px 时） |
| 区域右下角 (0.12, 0.6) | −16.5° | +20mm |

另外贴着左边缘（u ≈ 0）的框会被 `EDGE_MARGIN` 判为碰边，**根本不发位置帧**。

而任务里记的 ghost 读数是 **+4.2°、Y +17~19mm**。如果这是 K230 的原始读数，那被锁住的东西应该在显示画面**大约 (0.60, 0.59)**
（中间稍偏右下），不在左侧中间。可能的解释：
1. 记下来的是相对 `GOAL` 的**误差**而不是原始读数（对准日志里打印的是"误差 x=…"）——那要看 `calib.json` 里 `GOAL` 是多少；
2. 那次锁住的是爪子的**另一部分**（另一只脚 / 爪子中间），不是左侧中间那只脚；
3. 画面方向和 `rotate_point` 不一致（`VO_FLAG_INVERT`）——但平时识别框能画在物块上，这个可能性小。

**明天第一件事**：按第 5 节第 1 步用标定模式看爪子被识别成什么、在哪。树莓派的 ghost 指纹不依赖画面位置（按读数认），可以兜住这种情况。
