## 1. 做了什么

| 文件 | 改动 |

## 2. 用法

```bash
python3 bench.py                     # 9 个位置 × 2 次，默认不用底盘（= main.py --once --no-chassis）
python3 bench.py --positions 2,5,8   # 只测这几个位置（也可以写 ②⑤⑧）
python3 bench.py --repeat 3          # 每个位置 3 次
python3 bench.py --resume            # 中途 Ctrl+C 退出后，从上一轮没测的位置继续
python3 bench.py --chassis / --step / --force   # 用底盘 / 单步 / 跳过启动前检查（和 main.py 一样）
python3 bench.py report [--last]     # 统计（--last 只看最近一轮）
```

### 2.1 测试流程
1. 启动时打印 9 个位置的说明，然后按"先每个位置测一遍、再测第二遍"的顺序提示：
   ```
   [5/18] 把物块放到 ⑤ 中·中：离相机（底座转轴正上方）约 18.6cm、正前方
       放好后回车开始（s = 跳过这次，q = 退出）：
   ```
   左右位置的说明，例如"④ 中·左：离相机约 18.6cm、往左偏约 10°（横向离中线约 3.3cm；对准时底座会转到约 -10°）"。
   **左 = 负角度**，和 config 的"底座右转为正"一致。
   近/远深度取 `calib.json` 里的 `REACH_NEAR_D` / `REACH_FAR_D`（真机是 156 / 216mm），中 = 两者中间（186mm）；
   只标了一个伸出姿态时用文档里的 15 / 18 / 21cm。（相机几乎在底座转轴上，R≈0，所以"离相机"≈"离转轴"）
2. 回车后用 `RealRunner.attempt()` 跑一次 `GraspTask.run_once()`。这和 `main.py --once` 是同一套代码，抓取逻辑没有复制。
3. 问：**真的抓到了吗** `[y/n/x]`（x = 这次不算，同一个位置重来）
4. 没抓到、而且机械臂伸出去过的话，接着问爪子偏哪边：左/右/前/后/高/低，可以写多个，也可以直接带毫米（`右4 前3`、`r4`）。
   没带毫米的方向会再问一次"偏右大概几毫米"，回车就是不知道。
   "前"的意思是落点比物块离车更远。
5. 备注（可选）。**每次测完立刻写一行**到 `logs/bench.csv`。

### 2.2 `logs/bench.csv` 的列
`time, round, pos, row, col, depth_mm, angle_deg, chassis, result（程序结果）, truth（真实 1/0）, dev_dirs, dev_lr_mm（右正）,
dev_fb_mm（前正）, dev_ud_mm（高正）, note, x_deg, y, d（伸出时的物块位置）, base_deg, lift_cm, t（深度插值）, trim_deg, attempts, steps, time_s`

偏差按轴存成带符号的数，统计起来方便。列以后变了，旧文件会改名留档，和 `steps.csv` 的做法一样。

### 2.3 Ctrl+C / 续测
- Ctrl+C 之后会关闭设备：升降轴发 `E` 急停，底盘停车。已经测完的都在 csv 里，最后打印续测命令。
- `--resume`：找到 csv 的最后一轮（`round`），按这次的 `--positions/--repeat` 计划扣掉已经测过的次数，从剩下的接着测，
  仍然记在同一轮下。上一轮已经测完时开新一轮。

### 2.4 `bench.py report` 输出（合成数据示例）
```
  共 18 次（1 轮）  真实抓到 12/18 = 67%   程序报成功 14 次，其中误报 2 次
按位置：真实成功率（误报次数）
              左（约−10°）       中（0°）           右（约+10°）
近（16cm）    ① 1/2 50%          ② 2/2 100%         ③ 1/2 50% 误报1
...
按位置：没抓到时爪子的平均偏差（右 / 前 / 高为正，mm；括号里是方向记录次数）
远            ⑦ 右5(1) 高3(1)    ⑧ 右4(2) 高3(2)    ⑨ —
程序结果 vs 真实结果：
  success         12        2           ← 误报
  grasp_failed    0         4
建议：
  · 多数位置偏右约 4mm → 运行 `python3 calib.py trim 4`（偏右写正数，可累加）
  · 远处偏高 → reach_far 标得不准，`calib.py teach far` 重标
  · 程序误报成功 2 次 → 把对应时间的 logs/run_*.log 里"观察确认"那几行发给我
```

### 2.5 建议规则
| 情况 | 建议 |
|---|---|
| 有左右偏差的位置（同一位置的多次记录取多数）都朝同一边，跨 ≥ 2 列，另一边很少（≤ 1/3） | 偏差毫米数取中位数，给出 `calib.py trim <偏右mm>` |
| 只有左列或只有右列偏 | 和底座角度有关，可能是回差 / 小角度不到位 → 任务 09，**先不要 trim** |
| 只有中间一列偏 | GOAL 的左右零点可能不准，多测几次再 trim |
| 前后 / 高低：多个深度都偏同一方向 | 重新 teach（两个姿态都偏） |
| 只有远处 / 近处偏 | `calib.py teach far` / `teach near` |
| 只有中间深度偏，或中间深度成功率比两端低 30 个百分点以上 | 插值误差 → reach_mid（任务 09） |
| 有误报 | 发 `run_*.log` 里的确认几行 |
| ≥ 9 次、成功率 ≥ 90%、没有误报 | 可以进入底盘联调（方案第 4 节） |

记录里出现了不同的 `trim_deg` 时，report 会提醒数据混在一起了，建议用 `--last`。

## 3. `main.py` 重构是否保持原行为

`run_real` 原来的每个分支都对应到 `RealRunner.attempt()` 的同一个分支：

| 情况 | 原来 | 现在 |
|---|---|---|
| 手柄接管 | 关串口、打印、等 1 秒、继续 | `attempt()` 关串口、打印、等 1 秒、返回 None → 继续 |
| 第一次打开设备 | `preflight`，不通过且没 `--force` 就打印后退出 | 抛 `PreflightFailed`（打印的文字和原来一样）→ 退出 |
| `--step` | 包 `StepProxy` | 一样（`set_devices`） |
| `ManualOverride` | 打印、继续 | 一样 |
| `DeviceError` | 打印、关设备；`--once` 就抛出，否则等 3 秒继续 | 一样 |
| `not_found` | 等 2 秒 | 一样 |
| Ctrl+C | 打印"手动停止"，`finally` 关设备 | 一样 |

只有一处细微差别：原来启动时等手柄检测线程的 1.2 秒在 `try` 外面，这段时间按 Ctrl+C 会直接打印 Python 的错误堆栈；
现在这 1.2 秒也在 `try` 里，按 Ctrl+C 会正常打印"手动停止"。`--sim` 和 `--check` 没有改。
selftest 里新加了两项检查：把 `main.run_real` 换成仿真设备后，`--once` 跑一次就停；启动前检查不通过就不启动。

## 5. 没在真机验证的
- 整个交互流程在 SSH 终端里的实际体验（中文对齐、提示长短）
- 真机上 `task.last_grasp["lift_cm"]` 取的是 `Lift.pos`（上一次运动结束时的位置），应该就是对准后的高度，但没核对
- 位置说明里的"横向约 3.3cm"是按深度 × tan10° 算的；物块放得准不准由人决定，建议在平台上画 9 个点
- 建议规则的阈值（多数 = 一半以上、另一边 ≤ 1/3、中间深度低 30 个百分点）是拍的，要等真实数据出来再调
