# 任务 08 报告：真机试验记录工具 `bench.py`

> 分支 `cloud/08-bench-tool`。**工具没有在真机上运行过**，只用仿真设备（`sim.py`）和假的键盘输入测过；真机的串口、急停走的是 `main.py` 现有代码。

## 做了什么

### 1. `raspberrypi/grasp/bench.py`（新）

| 命令 | 作用 |
|---|---|
| `python3 bench.py` | 按测试矩阵 9 个位置 × 2 次：提示放到哪 → 回车 → 自动抓一次 → 问真实结果 → 写 `logs/bench.csv` |
| `--positions 2,5,8` / `--repeat 3` | 只测指定位置 / 每个位置测几次（也接受 `⑤` 这种圆圈编号） |
| `--resume` | 接着 `bench.csv` 里最新一轮没测完的继续（同一轮次号） |
| `--chassis` | 用底盘；**默认无底盘**（相当于 `main.py --no-chassis`） |
| `--step` / `--force` | 同 `main.py` |
| `--sim` | 用仿真代替真机，不接硬件练习这个工具；记到 `logs/bench_sim.csv`，不会混进真机记录 |
| `report` | 统计最新一轮；`--all` 全部轮次；`--round R` 指定一轮 |

**位置说明**（左右和 config 一致，底座右转为正）：

| | 左（底座约 −10°） | 中 | 右（底座约 +10°） |
|---|---|---|---|
| 近：离底座中心约 15cm | ① 往左约 2.6cm | ② 正前方 | ③ 往右约 2.6cm |
| 中：约 18cm | ④ 往左约 3.2cm | ⑤ | ⑥ 往右约 3.2cm |
| 远：约 21cm | ⑦ 往左约 3.7cm | ⑧ | ⑨ 往右约 3.7cm |

距离从机械臂底座中心（底座舵机转轴）量起；标定显示相机几乎在转轴上（R=0），所以约等于 K230 读到的深度。
三档距离都在真机标定的可抓范围 131~241mm 内；如果某台车的范围不包含它们，开始前会打印警告。
测试顺序是"每个位置先测一遍，再测第二遍"，同一位置的几次分散开。

**每次抓完问的问题**
1. `真的抓到了吗？[y / n / r=这次不算，重测]` —— 机械臂根本没伸出去时（not_found、ghost……）回车默认 n
2. 没抓到：`爪子偏哪边？[左l 右r 前f 后b 高u 低d，可组合如 右前/rf；回车=不知道]`，再问 `大概偏几毫米`
   （前 = 爪子落得比物块远、后 = 落得近、高 = 没够到、低 = 压到）
3. 抓到了：`爪子居中吗？回车=基本居中` —— 也可以输入偏的方向（抓到但偏了也是有用的数据）
4. `备注（可选）`

**`logs/bench.csv` 的列**：时间、轮次、位置编号和名称、是否用底盘、程序结果、真实结果、偏差方向、偏差毫米、备注、
对准时测到的物块位置 `x_deg / y / d`、底座角度、升降轴高度、深度插值 `t`、当时的 `GRASP_BASE_TRIM_DEG`、步数、尝试次数、用时、
本次运行日志文件名（误报时要看日志里"观察确认"那几行）。

**Ctrl+C**：抓取过程中按 → 升降轴发 `E` 急停、底盘停车（机械臂控制板没有急停指令，停在当前姿态），这一次不记录；
之前的每一次都是抓完立刻写盘的。等待输入时按 Ctrl+C 或输入 `q` 也一样安全退出。退出时提示还剩几次、用 `--resume` 继续。

**`report` 输出**
- 总成功率、误报（程序说抓到、实际没有）、漏报（实际抓到、程序说没有）、平均用时
- 3×3 表：每个位置 `抓到/次数` + 误报次数；再按深度（近/中/远）、按左右汇总
- 3×3 表：每个位置的平均偏差（如 `右4 前2`）
- 程序结果 vs 真实结果 混淆表
- **建议**（规则，偏差阈值 2mm）：
  - 多数位置同向偏左/右 → `python3 calib.py trim <偏右mm> <平均深度>`（取各位置平均偏差的中位数，不会被少数"居中"的位置拉小）
  - 只有右侧（或左侧）一列偏，其它不偏 → 和底座角度有关（回差 / 遮挡），先别用 trim，见任务 09
  - 右侧偏右、左侧偏左 → 底座转多了；反过来 → 小角度转不到位（任务 09）
  - 只有远处 / 近处偏高、偏低、偏前后 → `calib.py teach far` / `teach near` 重标；只有中间深度偏 → reach_mid（任务 09）；各深度都同向偏 → 两个姿态整体重标
  - 中间深度成功率比两端低 25 个百分点以上 → 插值误差，标 reach_mid
  - 有误报 → 把对应 `logs/run_*.log` 里确认那几行发过来；有 ghost / out_of_reach / lift_limit → 对应提示
  - 一轮里改过 trim（记录里 trim 值不止一个）→ 警告偏差统计混在一起
  - 成功率 ≥ 90% 且无误报 → 可以进入底盘联调

  日志同样用 `main.Tee` 写 `logs/run_*.log`，`steps.csv` / `episodes.csv` 照常记录。设备出错（含手柄接管）记为

  对准位置、底座角度、升降轴高度、插值 t、微调；`align` 后记下最后一次对准测量（没伸出去抓的那几次也有物块位置）

### 3. `selftest.py` 新增 `test_bench`（18 项）
用 `sim.py` 的设备，物块按测试矩阵的位置摆（仿真里深度按仿真标定的可抓范围等比例换算），用户输入换成假的 `input`：
- 位置说明、`--positions` 解析、偏差方向解析、测试顺序和 `--resume` 计划
- 跑 ① 和 ⑨（中间一次回答"r 重测"）→ 只记 2 条；记录里有对准位置、底座角度、t、微调、步数
- **① 的底座角度为负（−10.2°）、⑨ 为正（+10.3°）** —— 验证左右约定和 config 一致
- 运行中 Ctrl+C → 调用急停、已完成的已记录、这一次不记；之后 `--resume` 只测剩下的、同一轮；等待输入时 Ctrl+C 正常退出
- 统计和建议（构造的记录）：多数偏右 4mm → `calib.py trim 4`；只有右侧偏右 → 提示任务 09 且**不**建议 trim；
  只有远处偏高 → `teach far`；中间深度没抓到 → reach_mid；误报计数和日志提示；混淆表；`report` 默认只看最新一轮

## 没有在真机验证的
- 真机上 `bench.py` 整个流程（打开设备、自检、急停）。代码走的是 `main.py` 同一套函数，但 **Ctrl+C 时升降轴急停**
  这一步只在仿真里确认了"调用了急停"，没确认真机升降轴确实停下 —— 第一次用时请手放在电源旁边，故意按一次 Ctrl+C 看看
- 位置的距离（15/18/21cm）和 ±10° 是按方案文档的测试矩阵定的，是否都在这台车实际能抓的范围里，要看第一轮的 out_of_reach 次数；
  需要改就改 `bench.py` 开头的 `ROW_DEPTH_MM` / `COL_SIDE_DEG`
- 建议规则的阈值（2mm、25 个百分点）是拍的，等有真实数据再调
- 底座左转 10° 时物块"往左约 3.2cm"是按物块在底座转轴正前方的几何算的，摆的时候用尺子量个大概即可，程序会自己对准
