# 任务 08 报告：真机试验记录工具 `bench.py`

> 分支 `cloud/08-bench-tool`。**未在真机验证**：云端没有硬件，只用仿真设备和假输入测过。

## 做了什么

### 1. `raspberrypi/grasp/bench.py`（新）
| 命令 | 作用 |
|---|---|
| `python3 bench.py` | 按测试矩阵 9 个位置 × 2 次：提示放到哪 → 回车 → 自动抓一次 → 问真实结果 → 写 `logs/bench.csv` |
| `--positions 2,5,8` / `--repeat 3` | 只测指定位置 / 每个位置几次（顺序：先每个位置各一遍，再第二遍） |
| `--resume` | 接着最近一轮没测完的继续（按每个位置已测次数补齐） |
| `--chassis` / `--step` / `--force` | 用底盘（默认不用）/ 单步 / 跳过启动前检查，含义同 `main.py` |
| `--sim [SEED]` | 不接硬件，用仿真试用这个工具（会提示仿真的真实结果） |
| `report` / `report all` / `report <轮次>` | 统计最近一轮 / 全部 / 指定轮次 |

**位置说明**（和 `docs/抓取与调试方案.md` 3.2 节一致，左右按 config 约定"底座右转为正"）：
例如 `④ 中·左（离底座转轴约 18cm，往左约 10°，即正前方那条线往左约 3.2cm）`。
真机上相机几乎在底座转轴上（R≈0），所以"离底座转轴"≈ 观察姿态下相机前方的距离。

**每次抓完问的问题**
- 真的抓到了吗？`y / n / x`（x = 这次作废、重测，例如放歪了）
- 没抓到：爪子落点偏哪边？`左 l / 右 r / 前 f（伸过头）/ 后 b（没伸到）/ 高 u / 低 d / 回车=不知道`，大概几毫米
- 备注（可空）
- 程序根本没伸爪（`not_found`、`out_of_reach`、`ghost` 等）时不问，自动记"没抓到 / 未伸爪"
- 测到的物块深度和该位置差 35mm 以上时提醒"放对位置了吗"

**`logs/bench.csv` 的列**：时间、轮次、位置编号/名称、第几次、程序结果、真实结果、偏差方向、偏差毫米、备注、
对准时测到的物块位置 `x_deg / y / d`、底座角度、升降轴高度、深度插值 `t`、当时的 `GRASP_BASE_TRIM_DEG`、
步数、尝试次数、用时、是否用底盘、对应的 `run_*.log` 文件名。

**`report` 输出**
1. 3×3 表：真实成功率（抓到/次数）+ 误报次数
2. 3×3 表：没抓到时的平均偏差（例如 `右4×2 低3`）
3. 3×3 表：对准时测到的物块深度和底座角度（检查物块是不是放对了位置）
4. 程序结果 vs 真实结果的混淆表（标出误报、漏报）
5. 建议（规则）：
   - 左右：**多数位置**同向偏、且不止一列 → `python3 calib.py trim <mm> <平均深度>`；
     只有**右侧（或左侧）一列**偏 → "和底座角度有关，可能是回差或遮挡，见任务 09，先别用 trim"
   - 前后 / 高低：只集中在某一行 → 近处 `teach near`、远处 `teach far`、中间 `reach_mid（任务 09）`；多数位置都偏 → 重标
   - 中间深度成功率比两端低 25% 以上 → 插值误差，`reach_mid`
   - 有误报 → 让你把对应 `run_*.log` 的"观察确认"几行发过来
   - 一轮里微调值不同会提示"偏差统计会混在一起"

**中途退出**：等待输入或抓取过程中按 Ctrl+C（或输入结束）→ `RealSession.close()` 关设备，其中升降轴发 `E` 急停、底盘停车；
已完成的每一次都是当场写进 CSV 的，正在进行的那次不记；下次 `--resume` 补上。

### 2. 复用 `main.py`，没有复制抓取逻辑
- 把 `run_real` 里"开设备 → 启动前检查 → 建 GraspTask → 跑一次 → 设备出错关设备"抽成 `main.RealSession`，
  `run_real` 和 `bench.py` 共用。`main.py` 的命令行参数、输出文字和流程顺序都没变（手柄接管、设备错误重开、`--once` 遇设备错误抛出、`not_found` 后等 2 秒）。
- bench 真机模式同样把输出存到 `logs/run_*.log`，`episodes.csv` / `steps.csv` 照常写（GraspTask 本身写的）。

### 3. `task.py` 小改（不影响流程）
- `run_once` 开头 `last_grasp = None`；`grasp()` 里记下伸爪时的 `x_deg / y / d / 底座角度 / 升降高度 / t / 微调`，给 bench 用。
- 仿真升降轴没有 `pos` 属性时读一次 `position()`（真机 preflight 之后总有 `pos`，不会多发串口指令）。

## 没在真机验证的
- `RealRunner` 真机路径（开串口、preflight、Ctrl+C 时升降轴急停）只在仿真里用替身测过；第一次建议
  `python3 bench.py --positions 5 --repeat 1 --step` 试一下
- 中文提示在 SSH 终端里的对齐（表格按全角字符算宽度，终端字体不同可能略歪）
- 建议规则的阈值（偏差 ≥1.5mm 算偏、多数 = 超过一半的有数据位置、深度提醒 35mm）是拍的，用一两轮真机数据再调

## 使用建议
1. 每轮：`python3 bench.py` → `python3 bench.py report` + `python3 report.py`，两份输出一起发过来
2. 调完 `calib.py trim` 后开新的一轮（不要 `--resume`），`report` 默认只统计最近一轮
3. 回答偏差方向时以"爪子落点相对物块"为准：爪子在物块右边 = 右
