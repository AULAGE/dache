# 任务 04 报告：K230 识别程序审查与提速

> 分支：`cloud/04-k230-review`　|　改动文件：`k230_sdcard/main.py`、新增 `k230_sdcard/tests/`、`k230_sdcard/tools/depth_fit.py`
>
> ⚠️ **全部未在真机验证**。云端没有 K230、没有 CanMV 环境。本报告里的 bug 是读代码发现、再用 CPython + numpy
> 离线复现的；**所有耗时数字都是估计**（numpy 和 ulab 速度差很多），以板子上 `Profiler` 的输出为准。

## 0. 一句话结论

- **找到 3 个会影响串口输出的 bug**（都已加开关修好，默认关闭保持原行为）：旋转框角度回绕时宽高没互换（长方形目标测深最多偏 30%）、
  旋转框拟合失败时沿用的旧框原地不动（最多发 3 帧旧位置）、深度 < 0.5mm 时被截成 D=0 冒充心跳。另有若干低风险问题只记录不改。
- **提速**：代码里能做的（结果不变的几项）估计能从 ~143ms/帧省 10~30ms（约 7 → 8~9.5 帧/秒，**估计**）；
  真正的大头是 **KPU 推理（640×640）**，而且当前的 letterbox 让 **44% 的输入像素是灰边**——换成 640×384 的模型可以白省 ~40% 的 KPU 计算，
  不用改代码（`deploy_config.json` 里的 `img_size` 程序会自动读）。
- **深度**：默认的畸变系数 `dist_coeffs = [-0.2, 0.1, ...]` 看起来是没标定的占位值；如果镜头实际畸变没这么大，
  **画面边上深度会偏小最多 16%**（离线测试量化）。中心附近不受影响。给了标定步骤和拟合工具。
- 帧率提上去以后，**`UART_INTERVAL_MS = 100` 会把位置帧限制在 ≤10Hz**（超过 10 帧/秒时等于隔帧发），记得一起改小。

### 检查过、没发现问题的地方

- **坐标旋转**：`rotate_point`/`rotate_box`（90° 顺时针 `(x,y)→(H−y, x)`）互相一致；`compute_position` 在 `ROTATE_DEG=90` 下
  原始画面往上 = X 正、往右 = Y 正，符合"X 右、Y 下"，和树莓派实测一致（测试 `TestGeometry`）。
- **边缘判断** `touches_edge`（848）：合成了物块伸出画面右边 3/20/70px、转 0°/20°/40° 的情况，全部正确判为碰边（不发位置帧）。
- **畸变校正** `undistort_point`：确实是 OpenCV (k1,k2,p1,p2,k3) 模型的反函数，迭代收敛到 0.05px 以内。
- **时间戳回绕**：所有时间差都用了 `time.ticks_diff`，写法正确。只有 `last_send_time = 0`（1098）这个初值在
  "ticks 周期为 2³⁰（32 位 MicroPython）且开机超过 6.2 天"时会让第一次发送被推迟；K230 大核是 64 位，周期大得多，**实际不会触发**。
  `Profiler` 的 `ticks_us` 在 32 位下 17.9 分钟回绕一次，单帧计时远小于半周期，也没问题。
- **异常处理**：所有 `except` 都放行了 IDE 停止信号；`finally: cleanup()` 能释放摄像头。主循环出错只计数打印，不会卡死。
- **协议**：帧格式、CRC8 和树莓派 `devices.K230` 的解析完全对得上（测试 `TestProtocol`）。
- **跟踪器平滑延迟**：相机动一下（目标跳 5~40px）后，平滑输出 ≤3 帧就落到 1px 以内（7 帧/秒下 ≈0.4 秒）。
  这是树莓派每步要等几帧的原因之一；提速后同样的帧数用的时间更短（`ALPHA_*` 已按实际帧间隔换算）。

### 3.1 `Profiler` 统计了哪些阶段

`DEBUG_TIMING = True` 时每 30 帧打印一行 `[timing ms/frame] capture | ai2d+kpu | post | select | refine | pos+draw | show+gc | total (fps)`：

| 阶段 | 包含的代码 | 估计耗时（**没测过，按 K230 常见数据推的**） | 说明 |
|---|---|---|---|
| `capture` | `sensor.snapshot` | 5~35ms | 含等下一帧（传感器 30fps）；处理慢时多半很短 |

## 4. 深度精度

### 4.1 公式

```
size_pix = max(两组对边的平均长度)          # 畸变校正后的 4 个角点
D = BLOCK_REAL_SIZE × FOCAL_PIX / size_pix × DEPTH_SCALE + DEPTH_OFFSET
X = (u − 画面中心) × D / FOCAL_PIX           # 旋转到正向画面后
```

一个有用的结论：`DEPTH_OFFSET = 0` 时 `X = Δu × 边长 × DEPTH_SCALE / size_pix`，**和 FOCAL_PIX 无关**——焦距标错只影响深度、不影响 X/Y。

### 4.2 误差来源（按影响大小排）

1. **畸变系数没标定**（`dist_coeffs = [-0.2, 0.1, 0, 0, 0]`、`USE_UNDISTORT = True`，第 35~36 行注释自己写着"未标定请关掉"）。
   离线量化（理想无畸变镜头 + 默认系数）：

   | 物块中心 x（1280 宽） | 640（中心） | 800 | 960 | 1100 | 1200 |
   |---|---|---|---|---|---|
   | y=360 时深度误差 | 0% | −1.7% | −6.5% | −12.3% | −16.0% |

   镜头实际畸变越接近这组数越好；不知道就按 4.3 步骤 1 测。X/Y 也一起偏。
2. **侧面算进物块**：`SHADE_TOLERANT = True` 让"亮面/暗面都算同色"，相机斜着看时立方体的侧面会被并进掩膜 → 框变大 → **深度偏近**。
   腕部相机角度变化大时这个误差也跟着变。
3. **焦距 / 偏移**：`FOCAL_PIX = 944` 和 `DEPTH_SCALE/OFFSET = 1/0` 是否标过不确定；距离是从镜头光心算起，尺子量的是到镜头前端，差一个常数 → `DEPTH_OFFSET`。
4. **斜视**：顶面不正对镜头时一个方向被压缩 cos(倾角)；取最长边能抵消绕一个轴的倾斜，两个轴都斜时偏远。
5. **主点不在中心**（B8）：X/Y 的常数偏移，树莓派 `GOAL` 按 K230 读数标定，会吸收掉。
6. **算法本身**：理想合成图上 40~300px、0~89° 各种情况，深度误差 < 2.5%，中心误差 < 1px（测试 `test_refine_accuracy_squares`）。

**对抓取的影响**：树莓派的 `GOAL` 是按 K230 读数标的，所以"在目标位置上"的系统误差会抵消；系统误差主要影响**离目标远时的前馈步长**
（画面边上 X/D 偏得多 → 多走几步才对准）。所以标定的目标是**整个画面里一致**，不一定要绝对准。

### 4.3 标定步骤

工具：`k230_sdcard/tools/depth_fit.py`（CPython，标准库，在电脑或树莓派上跑）。新版 `Object:` 行有 `S:` 像素边长。

1. **先查畸变**（决定 `USE_UNDISTORT`）：物块平放，相机正对桌面、高度固定（例如 200mm），把物块依次放在画面中心、左右边、四个角
   （别碰边），每处用 `python3 calib.py watch` 记 10 秒深度中位数。
   - 各处差 < 3%：保持现状。
   - 边上明显**偏小**：默认系数校正过头，改 `USE_UNDISTORT = False` 再测一次，选更平的那个。
   - 边上明显**偏大**：镜头畸变比默认更大，需要正式标定：用 CanMV IDE 存 15~20 张 1280×720 的棋盘格照片（不同角度/位置），
     电脑上 OpenCV `calibrateCamera` 得 `fx, fy, cx, cy, k1, k2, p1, p2, k3`；`fx` 填 `FOCAL_PIX`，后五个填 `dist_coeffs`。
     （程序假设 `fx = fy`、主点在正中；OpenCV 算出的主点离中心很远时告诉我，再加主点参数。）
2. **焦距 + 偏移**：物块放在画面中心，用尺子量镜头前端到物块顶面的距离，取 5~6 个距离（覆盖实际抓取范围，例如 80/120/160/200/250/300mm），
   每个距离记 `Object:` 行的 `D` 和 `S` 中位数，写成 CSV：
   ```
   # 真实距离mm, D, S
   80, 77.9, 290.1
   ...
   ```
   ```bash
   python3 k230_sdcard/tools/depth_fit.py data.csv --size 24
   ```
   把打印的 `FOCAL_PIX`、`DEPTH_SCALE = 1`、`DEPTH_OFFSET` 写进 `main.py`。拟合后最大误差 > 5mm 说明读数不稳或物块没正对。
   （只有 `D` 没有 `S` 时也能拟合：`--scale`/`--offset` 填采数据时板子上的值，输出新的 `DEPTH_SCALE`/`DEPTH_OFFSET`。）
   旧的 `CALIB_DISTANCE_MM` 单点模式也能用，但只能得到焦距、得不到偏移。
3. **横向检查**：深度固定，物块左右平移已知距离（±20、±40mm），看 X 的变化量；差 > 5% 再检查 `BLOCK_REAL_SIZE`（物块实际边长）。
4. **树莓派重标 `GOAL`**：K230 读数的单位变了，`python3 calib.py goal` 重新标一次（见 `raspberrypi/README.md`）。

## 6. 真机验证清单

准备：用本分支的 `k230_sdcard/main.py` 替换板子 SD 卡上原来的 `main.py`（**先备份旧文件**；模型和 `deploy_config.json` 不用动）。
每一步只改一个开关，记 3 行 `[timing ...]`（`DEBUG_TIMING = True` 已默认开）和 `calib.py watch` 30 秒的读数。

| 步 | 改什么 | 看什么 | 期望 / 判断 |
|---|---|---|---|
| 0 | 不改（默认配置） | Profiler 各阶段真实耗时、FPS；`calib.py watch` 静止物块的 D/X/Y 均值和抖动；树莓派 `main.py --check` 2 秒帧数 | 和旧程序一样（≈14 帧/2 秒）。**把这一行 timing 发给我**，后面的估计就能换成实测 |
| 1 | 看启动打印 | `FAST_OBB_POINTS: on` 还是 `off` | `off` 说明 ulab 不支持布尔下标，S1 无效（不会出错） |
| 2 | `FAST_OBB_POINTS = False` ↔ `True` | `refine` 一栏 | `True` 时 `refine` 变小；`calib.py watch` 读数不变 |
| 3 | `PROFILE_DETAIL = True` | `[timing detail]` 一行 | 找出 `r.color / r.mask / r.obb / r.subpix` 谁最大，决定下一步 |
| 4 | `OSD_EVERY = 3` | `pos+draw`、`show+gc` | 两栏都变小；HDMI/IDE 画面变卡是正常的 |
| 5 | `PRINT_OBJECT = False` | `pos+draw` | 连着 IDE 时略小 |
| 6 | `GC_MIN_FREE_KB`：先临时加一行 `print(gc.mem_free())` 看空闲内存，设成其 1/3 | `show+gc`；连续跑 10 分钟 | 变小且不报 MemoryError；报错就改回 0 |
| 7 | `REFINE_GRID_CEIL = True` | 物块放远（~300mm）静止：`refine` 和 D 的均值/抖动 | `refine` 变小，D 均值差 < 2%、抖动不明显变大 |
| 8 | `FIX_OBB_ANGLE_WRAP = True` | 物块转到 ~0° 或 ~88°，用手指/爪子挡住一部分（让可见部分是长方形），看 OSD 框和 `calib.py watch` 的 D | 原版：框偶尔转 90°、D 跳变；修复后框贴合、D 稳定。正方形不挡时两者一样 |
| 9 | `FIX_STALE_OBB = True` | 物块被挡一部分时慢慢移动相机（或物块）；看 OSD 框是否跟手、D/X 有没有"卡住一下再跳" | 修复后不卡顿 |
| 10 | `FIX_DEPTH_NONZERO = True` | 正常情况下无变化 | 没变化就对了 |
| 11 | 帧率 >10 后 `UART_INTERVAL_MS = 50` | 树莓派 `--check` 2 秒帧数 | ≈ 2 × 帧率 |
| 12 | 深度标定（第 4.3 节） | `depth_fit.py` 拟合误差；之后 `calib.py goal` | 拟合后误差 < 5mm |
| 13 | （可选，大改）640×384 / 320×192 模型 | `ai2d+kpu`；识别率 | KPU 时间按像素数成比例下降；识别不掉帧 |
| 14 | 整套抓取 | 每次抓取的对准步数和总时间（和改之前比） | 步数不变或更少，时间更短 |

建议的上车配置（都确认过以后）：`FIX_OBB_ANGLE_WRAP = FIX_STALE_OBB = FIX_DEPTH_NONZERO = True`、`OSD_EVERY = 3`、`PRINT_OBJECT = False`，
其余看步骤 0~7 的数据决定。

## 7. 还没在真机验证的（全部）
