# 任务 03：底盘固件分析（只读）→ 改进树莓派端底盘驱动

## 背景
底盘是 WHEELTEC 的 STM32F407 控制器（阿克曼转向），固件源码在 `底盘代码/大车底盘/`（Keil 工程，FreeRTOS，**GBK 编码**）。
树莓派通过 USB 串口（`/dev/ttyACM0`，115200）控制它，驱动是 `raspberrypi/grasp/devices.py` 的 `WheeltecChassis`。

真机实测（2026-11-02）：
- 让它走 100mm（100mm/s），在 97mm 处给 0 速度，实际走了 145~148mm——**松油门后滑了约 45mm**
- 里程计（回传 vx 积分）和尺子量的误差约 2%
- 直走时航向变化约 −2°（转向可能没回正）
- 回传帧约 20Hz，电压字段 ≈ 25.8V

现在的驱动用"剩余距离 ≤ τ × 实际速度 时松油门"，τ 自适应（离线测试 2~3 次收敛到 ±3mm，但没在真机验证）。

## 要查清楚的（读固件源码）
1. **速度平滑** `Smooth_control()`（`BALANCE/balance.c` 附近）：算法、步长、多少毫秒到达目标速度；串口控制时是否启用（只对全向车？）
2. **串口指令超时**：多久没收到帧会自动停车？（决定驱动 50Hz 发送是否必要、断线是否安全）
3. **下发帧**：`vx / vy / wz` 的单位和限幅；阿克曼车型 `wz` 怎么换算成转角；**vx=0 时 wz 会怎样**；倒车时 wz 的符号约定
4. **回传帧** 24 字节每个字段的含义和单位（尤其 flag 字节、wz 的来源是编码器还是陀螺仪、加速度和角速度的量程）
5. **最小转弯半径 / 最大转角**（车型参数，`robot_select_init.c`）——树莓派端 `ACK_MIN_RADIUS_MM` 现在是猜的 600
6. 有没有**位置模式**或"走指定距离"的指令（有的话可以替代树莓派端的刹车估算）
7. 固件里有没有其他会让车动的输入源（PS2 手柄、蓝牙 APP、CAN、航模遥控）可能和串口控制冲突，切换规则是什么
8. 低电压保护阈值（树莓派端 `BATTERY_MIN_V = 22.0` 合不合理）

## 然后改进驱动
- 根据查到的平滑算法，在 `WheeltecChassis.drive` 里用**模型预测**松油门时机（保留现在的自适应 τ 作为兜底），
  并更新 `selftest.py` 的假控制器让它按固件的真实平滑算法响应
- `ACK_MIN_RADIUS_MM` 等参数按固件给出准确值（写进 `config.py` 默认值，注明出处 文件:行号）
- 如果查到超时停车时间，确认驱动的发送频率和异常退出时的安全性
