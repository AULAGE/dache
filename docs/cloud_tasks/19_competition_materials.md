## 背景
ROBOTAC 甘肃赛区创意机器人设计赛，提交：作品信息概要表、作品设计报告、演示 PPT（+ PDF）、源代码与素材。

真机成功率数据、照片、视频**还没有**（用户这几天在测、在拍）。

## 目标
### 1. 一键生成脚本 `docs/robotac/build/build_materials.py`
- 输入：`docs/robotac/设计报告_v2_草稿.md`（正文）、`docs/robotac/build/data.json`（真机数据、队员信息等可变内容）、`docs/robotac/build/media/`（照片、截图、视频）
- 输出到 `docs/robotac/build/out/`：`设计报告_*.docx`、`答辩PPT_*.pptx`、`作品信息概要表_*.docx`（PDF 由用户在 Windows 上用 Office 导出，脚本里提供可选的 LibreOffice 转换）
- **用模板的样式**（标题层级、正文、表格、图注、封面、目录、页眉页脚）：基于 `templates/` 里的旧文件改，不要从零排版；目录要能在 Word 里"更新域"刷新
- 数据驱动：`data.json` 里没填的字段，在文档里用**黄色高亮的占位**显示（例如"【待真机：低平台无底盘成功率】"），一眼能看到还缺什么；填上后重新运行即可
- `data.json` 给出完整的字段模板 + 注释（bench 统计表、各阶段用时、平台高度、视频文件名、照片文件名、需要核对的事实）
### 2. 设计报告 docx
- 正文按 `设计报告_v2_草稿.md`；草稿里的【请核对】保留为高亮占位
- **新画两张图**（PNG，中文字体要正常显示，必要时安装 Noto Sans CJK 并检查渲染）：系统总体架构（树莓派居中、四路串口、各下位机）；眼在手上自适应视觉伺服流程（测量→误差→u=−α·e/(J·s)→执行→再测→学习 J）
- 补充 17/18 的安全修复（升降复位保护、SIGTERM 停车、底盘回传中断停车、搜索复核、深度跳变确认、后退上限）和 16 的看板到第 3.6、4.3 节
- 测试章节：bench 3×3 表格的结构做好，数据从 `data.json` 填
### 3. 答辩 PPT（约 18~22 页，沿用旧 PPT 的版式和配色）
- 结构建议：封面 → 痛点 → 方案总览 → 硬件 → 视觉测距 → 自适应视觉伺服（核心，2 页）→ 安全与容错 → 抓取确认与学习 → 开发方法（自测+仿真+测试矩阵）→ 问题与解决 → 版本迭代对比 → 测试结果（数据页）→ 演示视频（按拍摄清单 ①③④⑤⑦⑧ 留视频位）→ 创新点 → 展望 → 致谢
- **每页写讲稿**（备注栏，中文口语，每页 30~60 秒）
- 视频：脚本支持把 `media/` 里的视频按文件名嵌入对应视频位；没有时显示占位框和片段说明
### 4. 作品信息概要表：按新系统更新技术内容，队员/分工等个人信息从旧表照搬并标【请核对】
### 5. 答辩问答准备 `docs/robotac/答辩问答.md`：20~30 个评委可能问的问题 + 回答要点（结合代码和测试，**不编数据**；没数据的写"如何如实回答"）
