# 任务 02：让仿真更真实

## 背景
`raspberrypi/grasp/sim.py` 是抓取流程的仿真环境，任务 01 要在它上面搜参数。仿真越接近真实，搜出来的参数越可信。
现在已经模拟了：深度系统误差（每台车固定）、测量噪声、3% 丢帧、K230 约 7 帧/秒、物块碰画面边缘不发帧、
900mm 外识别不到、相机半径量错、阿克曼最小转弯半径、底盘 ±5% 误差和跑偏、里程计误差、机械爪抓取容差、10% 随机抓取失败。

## 要加的真实因素（按重要性）
1. **K230 跟踪器的"预测"状态**：板子程序（`k230_sdcard/main.py`，看 `Tracker` 类和 `holding`）丢帧时会预测位置但不发帧；
   刚移动完的几帧可能是旧位置（运动模糊、滤波滞后）。仿真里：动作后的前 N 帧带滞后（按动作幅度）
2. **底盘控制器速度平滑**：真机松油门后还会滑行（实测 100mm/s 时滑约 45mm，详见 `raspberrypi/README.md` 和 `devices.WheeltecChassis.drive` 的注释）。
   现在仿真的 `SimChassis.drive` 是"走多少就是多少 ±5%"，没有经过 `WheeltecChassis` 的刹车逻辑。
   改成：仿真底盘也走同一套 `drive()` 逻辑（用一阶滞后模型产生假回传帧，参考 `selftest.py` 的 `test_chassis`），这样停车误差是真实的
3. **舵机回差和死区**：小于约 5us 的指令不动；换方向时有约 10us 回差。影响底座小角度修正
4. **机械臂伸出碰歪物块**：伸出姿态和物块有小偏差时，有概率把物块推开 10~30mm（以后重新对准）
5. **深度测量随距离非线性**：尺寸法测深，误差随距离平方增长；近处物块大、碰边缘的概率高
6. **USB 掉线**：机械臂 CH340 偶尔掉线 0.5~2 秒（实测会这样），`Arm.move` 有重连逻辑，仿真里注入掉线测试它
7. **误识别**：偶尔出现一个假目标（别的东西被认成物块），持续几帧

## 要求
- 每个新因素都用 `config.py` 里的开关和强度参数控制（例如 `SIM_SERVO_DEADBAND_US = 5`），**默认开启真实值**，可以关掉做对比
- 改完后报告：每加一项，成功率/步数/用时变化多少（一项一项加，表格）
- 如果某个因素让成功率明显下降，**分析原因**并在报告里提出控制逻辑上的改进建议；
  能在 `task.py` 里低风险解决的可以改（必须有开关、默认保持原行为、`selftest.py` 通过、报告写明）
- `selftest.py` 的仿真回归阈值（85%）如果因为仿真更真实而达不到，**不要降低阈值**，而是在报告里说明并提出改进
